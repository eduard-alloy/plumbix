# WU-053: Validator model usage on the run result and the runs API

**Status**: ✅ Complete (2026-10-27) · **Features**: F-003, F-004 · **Estimate**: one session · **Kai**: 6G3SCZ (workstream F8QK66, milestone M2 PZTRDV) · **Decisions**: cost is reported, never computed (see CONSTRAINTS)

## Goal

Chart-AI, the governance pilot that observes Plumbix, must ingest each validator's model usage structured, not parsed from logs. Today a validator's `usage` survives only in the step log line that `usageNote` writes (`internal/engine/external.go`): `Combine` drops it when it builds the run result's `validators` list, so `GET /api/v1/runs/{id}` and `GET /api/v1/changes/{id}/runs` never show it. This unit carries it through.

## Design

- **Result.** `ValidatorOutcome` (`internal/validation/combine.go`) gains `Usage *Usage` with `json:"usage,omitempty"`, copied from the validator's verdict. Advisory validators included. Absent when the validator reported none (the reference validator calls no model) and for every run stored before this unit.
- **Storage and API.** The run result is stored as one JSON column (`store/runs.go`, `scanRun`), so the field persists and is served without further change. An API test reads a finished run back through both run endpoints and checks the JSON shape.
- **Contract.** `contracts/openapi.yaml`: the `ValidationResult` validators items gain `usage`, a `$ref` to a new `Usage` schema with the same fields, bounds and descriptions as `contracts/verdict.schema.json` (`model`, `input_tokens`, `output_tokens` required; `turns`, `cost_usd`, `reasoning_tokens`, `cache_read_tokens`, `cache_write_tokens` optional). `contracts/events.schema.json` does not change: the consumer fetches the run on `verdict.issued`.
- **Honesty.** `cost_usd` is whatever the validator's runtime reported. Plumbix never computes, converts, estimates or defaults it. The contract keeps the wording on who reported it. A consumer treats a missing `cost_usd` as unknown cost.
- **Consumer.** On `verdict.issued` (which carries `run_id`), Chart-AI reads `result.validators[*].usage` and attributes each one to `<instance>/validator/<name>`.
- Purely additive. No page change; `model.ts` gains the optional field so the web model matches the API.

## Fixes
2026-10-27, review of the landing change c_dm5twlg3ipza: approved, two minor findings.
- Pre-existing `omitempty` on a plain `float64` dropped a reported zero `cost_usd`, which a consumer would read as unknown. Chart-AI confirmed on 2026-10-28 that absent and zero must stay distinct (requirement V1, no fabricated numbers). `Usage.CostUSD` is now `*float64`: nil when not reported, 0 when reported as zero; `claudecode.Result.TotalCostUSD` is a pointer too, so a result line without a cost never defaults to 0. Both contracts say "absent or null: cost not reported; 0: reported as zero" and accept null. Tests: `TestCostZeroIsReportedAndAbsentStaysAbsent`, `TestVerdictUsageKeepsCostOnlyWhenReported`, the valid example `usage-cost-zero.json`.
- "No web change" in Design read as if `model.ts` were untouched; it now says "No page change" (landed with the WU-048 follow-up).
