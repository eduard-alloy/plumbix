# WU-039: Verdict notes in every validator log, cached tokens in usage

**Status**: ✅ Complete (2026-10-19) · **Features**: F-003, F-004 · **Estimate**: half a session · **Kai**: 4XKP64

## Goal

The owner compared the `ai-review` and `ai-claude` logs, same model, and they read differently. The external step's log, written by the server, ended with the verdict: summary, findings and risks; a container validator's log held only what the container printed, so its findings were on the change page alone. And the token counts misled: "8 input tokens" for a 47,000-character prompt, because input read from or written to the prompt cache was not recorded. The loop keeps the owner's local Claude Code setup (decided with the owner); only the logs and the numbers change.

## Design

**Notes everywhere.** After the run, the engine appends the same verdict notes it writes for an external step (verdict line with usage, the rest of the summary, `finding` and `risk` lines) to each container validator's log, after what the container printed. External steps keep theirs; plain steps and validators without a verdict get none.

**Cached tokens.** `validation.Usage` gains `cache_read_tokens` and `cache_write_tokens` (optional, in the verdict schema); `input_tokens` counts only uncached input, so the three add up to the prompt. Claude Code (loop and image) reads them from the result's `cache_read_input_tokens` and `cache_creation_input_tokens` through `claudecode.Result.VerdictUsage`; the Anthropic API validator from the response usage; an OpenAI-compatible provider's `prompt_tokens_details.cached_tokens` becomes cache reads and is taken out of input. The notes and both container validators' final lines show them.
