# WU-016: Browser session and web serving

**Status**: ✅ Complete (2026-10-16) · **Features**: F-004, F-008 · **Estimate**: 6-7 hours

## Goal

Everything the web interface needs from the server, built and tested before any screen exists: a browser signs in from a one-time link printed by the CLI and stays signed in with a cookie; browser requests are checked against DNS rebinding and cross-site requests; a diff endpoint feeds the change screen; the binary serves the built web app. WU-011 and WU-017 then only build screens.

## Design

**Sign-in.** `plumbix login` calls `POST /api/v1/login-links` with the bearer token and prints `http://<listen>/login?t=<token>`. The page is the web app; it exchanges the token with `POST /api/v1/sessions` (no auth, a browser request), which sets the cookie `plumbix_session` (HttpOnly, SameSite=Strict, Path=/, 30 days) and answers `{status: "signed_in", expires_at}`. A link works once: a second exchange answers 401 `link_used`; after 10 minutes, 401 `link_expired`; an unknown token, 401 `link_invalid`. Only hashes (SHA-256) of link and session tokens are stored; tokens are 32 random bytes, base64url.

**Browser checks.** A request authenticates with the bearer token as before, or with the session cookie. Cookie requests must carry a `Host` equal to the server's listen address (DNS rebinding defence), and state-changing methods must carry an `Origin` of `http://<that host>` (cross-site defence on top of SameSite); a mismatch is 403 `forbidden`. Bearer requests are not subject to either check.

**Sign-out.** `DELETE /api/v1/sessions/current` (cookie) ends this browser's session and clears the cookie. `DELETE /api/v1/sessions` (bearer, from `plumbix logout`) revokes every browser session. `GET /api/v1/session` tells the app whether it is signed in and until when. Expired links and sessions are deleted whenever a link is created.

**Diff.** `GET /api/v1/changes/{id}/diff` returns the diff of the latest run that has a head: `{base, head, additions, deletions, truncated, files[]}`; each file has `path`, `status` (added, modified, deleted), `binary`, `additions`, `deletions` and `hunks[]` of `{old_start, old_lines, new_start, new_lines, header, lines[{type: context|add|del, old?, new?, text}]}`. `?stat=true` omits hunks. A diff over 4 MiB comes back as stats only with `truncated: true`. Renames are not detected, matching the rest of the engine. No run with a head yet: 409 `invalid_state`. A new `internal/diff` package parses unified diffs and is tested on its own.

**Web serving.** `web/` is a Vite project (React, TypeScript, no component library). `web/embed.go` embeds `web/dist` and serves it with SPA fallback to `index.html`; `/api/` stays on the API mux. Without a built app the root answers a short "web interface not built" page. IBM Plex Sans and Mono (400, 500, 600, OFL) are self-hosted from `web/public/fonts`. `tokens.css` from the handoff is used as is. `make web` builds the app; `make build` depends on it. This unit ships a one-screen app (wordmark, version from health) that proves the chain; the screens are WU-011 and WU-017.

**Not in scope.** Accounts, per-client tokens, anything cross-machine. The screens themselves.

## Acceptance criteria

- **AC-1**: `plumbix login` prints a one-time link; exchanging it signs the browser in; a second exchange reports `link_used`; after 10 minutes `link_expired`; an unknown token `link_invalid`. Only hashes are stored.
- **AC-2**: With the cookie, API calls succeed; with a foreign `Host` they are 401; state-changing calls without a matching `Origin` are 403; bearer-token calls are unchanged.
- **AC-3**: Signing out ends the session; `plumbix logout` revokes every session; sessions expire after 30 days.
- **AC-4**: The diff endpoint returns stats and parsed hunks for added, modified, deleted and binary files, matches its OpenAPI schema, honours `stat=true`, and is 409 before any run has a head.
- **AC-5**: The binary serves the built app at `/` with SPA fallback and keeps `/api/` protected; the container probe still gets no data; `make check` passes with and without the built app present.
- **AC-6**: `make check` and `make integration` pass.

**Decisions**
- A17 (Kai 01M531QTBA0GY1XAX4VX74YK96): one-time link, HttpOnly SameSite=Strict cookie, Host and Origin checks; the exchange is a POST so prefetchers cannot burn a link.
- `plumbix logout` revokes every browser session; a browser signs itself out from the app. The CLI has no way to name one browser.
- The diff is always the latest run with a head, so what the screen shows is what the last verdict judged. Older iterations are not diffable through the API; the iteration timeline shows outcomes, not diffs.
- IBM Plex Sans ships as one variable latin file (Google serves it that way), Mono as three static weights.
- The Vite dev server is not wired to the API (its Host and Origin would fail the checks). Develop against the built app for now.
