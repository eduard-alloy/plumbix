# WU-015: Plain git host

**Status**: ✅ Complete (2026-10-16) · **Features**: F-016 · **Estimate**: 2-3 hours
**Order**: after WU-008, before WU-009.

## Goal

A repository that lives only on this machine, or on any SSH server, can be registered and goes through the whole loop with no GitHub or Azure DevOps account: submit, validation, push detection, and later merge.

## Context

- Kai decision "Support plain git repos ... before the Azure DevOps adapter" (Q17).
- WU-008: host boundary, `gitops` with askpass auth, poller. The engine and poller already use plain git commands.
- CONSTRAINTS: tests never reach the network; secrets never in arguments.

## Design

- **Host kind `git`.** Accepted remotes:
  - an absolute local path, which must be a git repository (a bare repo, or a working repo for fetch-only use);
  - `file:///absolute/path`, with the same check;
  - `ssh://[user@]host[:port]/path` and scp-style `user@host:path`.
  Relative paths, `http(s)://` and anything else are rejected with a message pointing at the right host kind.
- **Plain adapter.** No credentials and no token expiry. SSH uses the user's own keys and agent.
- **No hanging prompts.** Git runs SSH in batch mode (`ssh -o BatchMode=yes`) unless the user set `GIT_SSH_COMMAND` or `GIT_SSH` themselves.
- **Docs.** A README quickstart that needs no account.

## Acceptance criteria

- **AC-1**: Registration accepts each valid remote form and rejects relative paths, missing paths, folders that aren't git repositories, and HTTP URLs, with clear messages.
- **AC-2**: The registry returns the plain adapter for `git` repos: anonymous, no expiry.
- **AC-3**: SSH runs in batch mode unless the user chose their own SSH command.
- **AC-4**: Through the real server, a local bare repo registered with `--host git` goes through submit and validation, and a push to it starts a plain run, with no URL redirection.
- **AC-5**: OpenAPI lists the new host kind, and responses still match.
- **AC-6**: `make check` and `make integration` pass.

**Decisions**
- Registration checks that a local path is a git repository, so a typo fails at once instead of on the first run.
- HTTPS remotes are refused for plain git and pointed at the GitHub or Azure DevOps host kinds, which know how to authenticate.
- Working repositories are accepted for fetching. Merging into them will need a branch that isn't checked out; the README recommends bare repositories.
