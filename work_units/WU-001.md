# WU-001: Project skeleton

**Status**: ✅ Complete (2026-10-15) · **Features**: none (foundation) · **Estimate**: 2-3 hours

## Goal

A Go module and single `plumbix` binary that starts a local-only HTTP server with a health endpoint, plus the test, lint and build commands every later work unit relies on.

## Context

- ARCHITECTURE.md sections 1, 2 (CLI, API, Config), 6 and 7.
- CONSTRAINTS.md: the server binds only to loopback and refuses anything else (Q12). No hardcoded runtime values: they come from config with documented defaults.
- Go 1.27 is installed. Module path: `github.com/eduard-alloy/plumbix`.

## Scope

**In**
- `go.mod`, `cmd/plumbix` with subcommands `serve` and `version`.
- `internal/config`: defaults, optional YAML config file, environment overrides, flag overrides, validation.
- Loopback enforcement: `server.listen` must resolve to a loopback address. An empty host such as `:6400` means all interfaces and is rejected.
- `internal/api`: HTTP server with `GET /api/v1/health` returning `{"status":"ok","version":"..."}`, structured logging with `log/slog`, graceful shutdown on interrupt or terminate signals.
- `contracts/openapi.yaml` with the health endpoint.
- `Makefile` with `build`, `test`, `lint` and `check` targets. Lint is `go vet` plus a `gofmt` check.
- `README.md` with a short description and build instructions.

**Out**
- Secrets loading (comes with the first step that needs secrets).
- Contract test tooling (WU-002 adds a JSON Schema validator, which the contract tests reuse).
- Web interface, storage, everything else.

## Config

| Key | Env | Flag | Default |
|-----|-----|------|---------|
| `server.listen` | `PLUMBIX_LISTEN` | `--listen` | `127.0.0.1:6400` |
| `data_dir` | `PLUMBIX_DATA_DIR` | `--data-dir` | `~/.plumbix` |
| config file path | `PLUMBIX_CONFIG` | `--config` | `<data_dir>/config.yaml`, optional |

Precedence: flag, then environment, then config file, then default. Unknown keys in the config file are errors.

## Acceptance criteria

- **AC-1**: `plumbix version` prints the version and exits 0. The version is set at build time and defaults to `dev`.
- **AC-2**: `plumbix serve` with defaults listens on `127.0.0.1:6400` and `GET /api/v1/health` returns 200 with `{"status":"ok","version":"<version>"}`.
- **AC-3**: `plumbix serve` refuses non-loopback addresses such as `0.0.0.0:6400`, `:6400` and `192.168.1.10:6400`, prints an error explaining why, and exits non-zero. `127.0.0.1`, `::1` and `localhost` are accepted.
- **AC-4**: Config precedence works as in the table above, and unknown config-file keys fail with an error naming the key.
- **AC-5**: The server shuts down cleanly when its context is cancelled or it receives an interrupt.
- **AC-6**: `make check` runs build, tests and lint, and passes. No TODOs, no debug prints.

## Steps (test first for each)

1. Module, `version` subcommand, Makefile. Test: `run([]string{"version"})` output and exit code.
2. Config defaults, file, environment and flag precedence. Tests for each layer and for unknown keys.
3. Loopback validation. Table test of accepted and rejected addresses.
4. Health handler. Test with `httptest`.
5. Server lifecycle: listen, serve, shut down on context cancel. Test on `127.0.0.1:0`.
6. Wire `serve` subcommand, including the refusal path. Tests through `run`.
7. OpenAPI file, README, `make check`.

**Decisions**
- Standard library `flag` for the CLI, no CLI framework. The command surface is small.
- `go.yaml.in/yaml/v3` for YAML. It is the maintained successor of `gopkg.in/yaml.v3` and will also parse pipeline files.
- Every API error uses the shared `{"error": {...}}` shape from the start, including unknown routes.
- `localhost` is accepted by name without a DNS lookup. Any other hostname is rejected.

**Discoveries** (added to CONSTRAINTS.md)
- The development sandbox blocks binding local ports, Go module downloads (certificate check through its proxy) and the Docker socket. Those commands run outside the sandbox.
