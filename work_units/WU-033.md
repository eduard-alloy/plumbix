# WU-033: Images page, own images with a Dockerfile editor

**Status**: ✅ Complete (2026-10-18) · **Features**: F-002, F-004 · **Estimate**: 1 session · **Kai**: MCJM55 · **Decision**: A32

## Goal

An operator can define an image on the Images page by writing its Dockerfile there, build it on the server, and reference it from a pipeline by name, so a validator or a build step no longer depends on an image someone built by hand somewhere. Validator images never come from the repository being judged (A32).

## Design

**Store.** An own image is a directory `<data_dir>/images/own/<name>/` holding `Dockerfile` (at most 64 KB, must contain a `FROM`); the directory is the build context, so a later unit can add files beside it. Names are one lowercase path component, `[a-z0-9][a-z0-9._-]{0,62}`, and may not be a shipped image's name. `images.Service` gains `ListOwn`, `GetOwn`, `PutOwn` and `DeleteOwn`.

**Build and status.** `Build` accepts an own name as well as a shipped one. An own image is tagged `<name>:latest`, which is what a pipeline's bare `image: <name>` resolves to, and labelled `org.plumbix.own=<name>` and `org.plumbix.dockerfile=<sha256 of the Dockerfile>`. Inspection compares the label with the stored Dockerfile: `current` when they match, `stale` when the Dockerfile changed since the build, `unlabelled` when the image was built outside Plumbix, `missing` when there is none. References are canonicalised so `my-validator` and `my-validator:latest` are the same image.

**API.** `GET /api/v1/images` lists own images too, each with `own: true` and its Dockerfile. `PUT /api/v1/images/own/{name}` with `{dockerfile}` creates or replaces one (400 with problems for a bad name, an empty or oversize file, a shipped name); `DELETE /api/v1/images/own/{name}` removes the definition (the local image, if built, stays until Docker prunes it; 404 when unknown). `POST /api/v1/images/{name}/build` builds it. All behind the session or token; none offered by the MCP server.

**Page.** An "Add an image" form (name, Dockerfile with a starter template) and, on each own card, the Dockerfile in an editor with Save, Build and Delete, plus the status line with the Dockerfile-changed warning. Deleting an image that pipelines still use asks for confirmation naming the steps.
