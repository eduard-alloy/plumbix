# WU-060: A person's approval names the person

**Status**: ✅ Complete (2026-10-29) · **Features**: F-010, F-001 · **Estimate**: one session · **Kai**: EBX2BZ (workstream F8QK66, milestone M2 PZTRDV) · **Follows**: WU-059

## Goal

Chart-AI's governed-path contract records a person's approval as an `Approval` event naming the person. Plumbix's `change.approved_by_person` event carries only the reason and the head, and the change's `human_approval` the same, so the adapter cannot say who. Two approval paths exist: the Approve action (API, CLI, web, the MCP tool) and an approving GitHub review by an owner, member or collaborator (WU-054), whose login today survives only inside the reason text.

## Design

- **Model** (`change.HumanApproval`): gains `by` (the person as the surface knew them) and `source` (`plumbix` for the Approve action, `github_review` for a GitHub review). `change.Approver{By, Source}` travels with the reason through `Engine.ApproveByPerson(ctx, id, who, reason)`; `by` is required, trimmed, at most 100 characters like `submitted_by`; an empty source is `plumbix`. The store keeps `approved_by` and `approved_source` (migration 0018) beside the reason, head and time, cleared with them by a new run; the event payload carries both, optional in `events.schema.json` so earlier events still validate.
- **Who the person is**: the API's approve body takes `by` beside `reason` and refuses without it. `plumbix change approve` gains `--by`, defaulting to `user@host` like the review loop's reviewer name. The MCP `approve_change` tool takes `by`, defaulting to the session identity (an agent approving under `--allow-approve` says so). The web Approve form asks for the name once and remembers it in the browser (`plumbix.approver`, local storage, best effort). A GitHub review approval names the reviewer's login with source `github_review`; its reason is the review's text, or "Approving review on GitHub" when the review has none.
- **Shown**: the change page says "Approved by eduard@mac · reason · 2 min ago" or "Approved on GitHub by lead · …"; OpenAPI's `human_approval` and the approve body carry the fields.
- **Not in this unit**: a Plumbix account or sign-in behind the name (the name is what the surface says; the browser session and the bearer token carry none); Chart-AI's adapter change (told separately, the fields are additive).
