# WU-061: GitHub integration per repository

**Status**: ✅ Complete (2026-10-28) · **Features**: F-010, F-004 · **Estimate**: one session · **Kai**: VQ5ZT3 (workstream F8QK66, milestone M2 PZTRDV) · **Follows**: WU-058 · **Precedes**: WU-059, WU-060

## Goal

The App's id and key are global settings, and rightly so: a GitHub App is created once under an account and installed per repository, so Plumbix keeps one per GitHub host, as it keeps the host token. But everything a person needs to know about the gate is per repository, and nothing in the browser says it:

1. whether the App is installed on this repository (without it, no check run is ever posted and the pull-request face silently falls back to the token),
2. whether `plumbix/gate` is required on each protected branch (the fact that turns a GitHub merge past a red gate into a recorded bypass rather than a `not_required` note, and the fact Chart-AI reads as one),
3. the pull-request and merger switches, which WU-055 left to the API and the CLI,
4. whether the repository is fed by the webhook or by polling.

This unit puts those four on the repository card, with the report behind them on the API and the CLI. An owner-level App override (a second organisation with a private App of its own) mirrors A20 and waits until a second owner exists.

## Design

- **Report** (`GET /api/v1/repos/{id}/github`, `internal/api/github.go`): computed live on request, never stored.
  ```json
  {
    "app": {"configured": true, "slug": "plumbix-gate", "installed": true, "message": "App plumbix-gate is installed on this repository"},
    "gate": [{"branch": "main", "required": true, "known": true, "message": "plumbix/gate is required on main"}],
    "intake": {"mode": "webhook", "webhook_secret_set": true, "last_delivery_at": "2026-10-28T21:03:00Z", "poll_interval": "15s"}
  }
  ```
  `app`: `host.GitHub.AppInstalled(ctx, repo)` asks `GET /repos/{owner}/{repo}/installation` as the App (200 installed, 404 not, anything else an error in words, the key never echoed); `configured` false with the message naming the two secrets when no App is set; `slug` from `GitHubApp.Check`, which now returns it, so the message can name the App and link its installation page (`https://github.com/apps/<slug>/installations/new`). `gate`: one entry per protected branch from `RequiredChecks`; `known` false carries the reason (administration read missing). `intake`: `mode` is `webhook` when `PLUMBIX_GITHUB_WEBHOOK_SECRET` is set, else `polling`; `last_delivery_at` is what the webhook handler remembers per repository since the server started (`pullrequest.Webhook` gains a small in-memory map), absent when none. A repository whose host is not GitHub gets 404 with "no GitHub integration for a <host> repository".
- **Switches**: the existing `PUT /repos/{id}/settings` with `pull_requests` and `merger` (WU-055); no new write path. The registration rules apply unchanged (`change.CheckRepoMerging`).
- **Web** (`ReposPage.tsx`): a **GitHub** button beside Token and Guidance on GitHub repositories only, opening a `GitHubPanel`: a "Pull requests gated" switch, a "Merged by" choice (GitHub / Plumbix) enabled when the switch is on, both saved on change through `api.updateRepoSettings` (the client function widens to send `pull_requests` and `merger` when given); a **Check** button that calls the report and renders each line in words with an ok/not-ok word, never colour alone; the not-installed line links the installation page; the not-required line says in words what it means for merges. The badge on the card's top line stays. The token panel is untouched.
- **CLI**: `plumbix repo github <id>` prints the report as JSON, like every other command.
- **Settings page**: the App rows say "One App per GitHub host. Whether it is installed on a repository is checked on the repository card."
- **Not in this unit**: an owner-level App override; creating or editing the webhook on GitHub (the README keeps the manual steps); Azure DevOps.
