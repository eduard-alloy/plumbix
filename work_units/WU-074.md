# WU-074: CONTRIBUTING.md and a bug-report path

**Status**: 🔄 In progress (2026-11-06) · **Features**: docs · **Estimate**: short · **Kai**: TS46MG (workstream XVACVT, milestone O1 HGFMS1) · **Follows**: WU-077 · **Source**: outside feedback of 2026-11-06, point 9; A48

## Goal

An outsider who lands on the repository knows within a minute whether code is taken, how a bug is reported, where questions go, how a security problem is reported without publishing it, and what to expect from one maintainer.

## What is wrong today

- No `CONTRIBUTING.md` and no `.github` directory, so GitHub offers nothing when someone opens an issue.
- `docs/server.md` still says "To contribute a change: push a branch, then submit it with its intent and acceptance criteria", which an outsider cannot do: they can neither push to this repository nor reach the maintainer's server.
- Issues are enabled on the repository; private vulnerability reporting was not until the owner turned it on during this unit.

## Design

1. **CONTRIBUTING.md** says plainly: outside code is not taken yet and why (every change lands through Plumbix with criteria before code, and the path for a second contributor does not exist); open an issue first for anything you want to build. Bugs through the template; questions and ideas as plain issues with the design documents named; security reports through GitHub's private vulnerability reporting, which the owner enabled for this unit; what to expect from one maintainer, and that planned work shows up in the roadmap.
2. **Issue template** `.github/ISSUE_TEMPLATE/bug_report.yml` with what you did, expected, happened, version, environment; `config.yml` keeps blank issues on and points at CONTRIBUTING.md for the rest.
3. **README** gains one sentence in "Plumbix validates itself" pointing at CONTRIBUTING.md; `docs/server.md` says that the branch-and-submit flow is how the maintainer lands changes, and points outsiders at CONTRIBUTING.md.
4. Enabling GitHub's private vulnerability reporting was the owner's setting, done by the owner on 2026-11-06 after iteration 2 held the change for exactly that; `docs-check` in the pipeline's `lint` step edits `.plumbix/pipeline.yaml`, which the guard holds for a person, so it goes as its own change right after this one.

## Acceptance criteria

| # | Criterion | Check |
|---|---|---|
| AC-1 | CONTRIBUTING.md says plainly whether outside code is taken, and how a bug is reported. | Read. |
| AC-2 | One issue template under `.github/ISSUE_TEMPLATE`. | `ls .github/ISSUE_TEMPLATE`; the YAML parses and has the fields GitHub's issue forms need. |
| AC-3 | The README's contribution line points at CONTRIBUTING.md and no longer tells an outsider to push a branch. | `grep CONTRIBUTING README.md docs/server.md`; `make docs-check`. |
