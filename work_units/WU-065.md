# WU-065: A repository can be paused or removed

**Status**: ✅ Complete (2026-10-30) · **Features**: F-001 · **Estimate**: short · **Kai**: QW668B (workstream F8QK66, milestone M2 PZTRDV) · **Follows**: WU-064 · **Source**: Chart-AI's first-day follow-up, ask 4

## Goal

There was no way to stop or retire a registration. A stale second registration of the same remote kept polling and raised `bypass_commit` for commits that had passed the gate on the other one.

## Design

- **Paused** (`Repo.Paused`, migration 0021): the poller skips the repository and the webhook's lookup does not match it; changes submitted through the API still run and merge. On the settings endpoint, `plumbix repo set --paused[=false]`, Pause and Resume on the card, a "Paused" badge.
- **Removed** (`DELETE /repos/{id}` with `by`, `plumbix repo remove --by`, Remove on the card with the person's name and an inline confirm): refused with `repo_busy` while a change of the repository is open or running, the check in the same transaction as the write (`Store.RemoveRepo`). Removal is soft: `removed_at` and `removed_by` are set, `GetRepo` and `ListRepos` skip the repository, the engine deletes the bare mirror, and the changes, runs, merges and events stay for the record, since the event stream is resumable by id and observers read history. `repo.removed` names who asked (`events.schema.json`).
- **Not in this unit**: deleting history; pausing a single branch; Azure DevOps webhooks.

## Fixes

**Iteration 1** (`approved`; five minor findings taken): `mirror` keeps its doc comment; a change is refused inside its own write when the repository was removed between the submission's check and the insert; a running triggered or branch run of the repository refuses the removal too, since it holds the mirror; README and OpenAPI say a removed repository's diffs and refreshes go with the mirror.

**Iteration 2** (`approved`; one of two notes taken, the other documented): `repos.url` was `UNIQUE`, so a removed registration still blocked registering the same remote, the very case this unit is for. Migration 0022 rebuilds `repos` without the column constraint and adds a unique index on live registrations only (`WHERE removed_at = ''`); the service test registers the remote again after a removal and refuses a second live one. The rebuild had to be done under the table's own name through a temp table, since the rename recipe fails the deferred foreign-key check on a populated database (CONSTRAINTS). Left as a documented narrow window: a poll that listed the repository just before its removal may re-create an empty mirror directory after `RemoveMirror`; harmless, and the repository lock keeps the deletion away from a fetch in flight.
