# WU-066: Criteria sets

**Status**: ⚪ Planned (2026-10-29) · **Features**: F-001, F-010, F-011 · **Kai**: X6Q5JY (workstream F8QK66, milestone M2 PZTRDV) · **Decision**: A43 · **After**: WU-063

## Goal

Acceptance criteria belong with the specification, written before the code by the person who owns the intent. WU-062's form puts them in the pull request body, where the author of the code writes and can edit them. A criteria set is a first-class object in Plumbix that a specification tool (Kai first) creates when the spec is settled; a change only names it.

## Design

- **Object**: `POST /api/v1/criteria-sets` with `task` (free text or a reference such as a Kai task), `owner`, `criteria[]` (the `CriterionInput` shape, checks included) returns `cs_<id>`; `GET /criteria-sets` and `GET /criteria-sets/{id}`; `PUT` edits a set no change has used and is refused afterwards (`criteria_set_used`). Written only through the API token or a browser session, so a pull request can never create one. `plumbix criteria add|list|show`.
- **Reference**: `criteria_set` on `ChangeInput`, or one line `Acceptance criteria: cs_<id>` in a pull request body. At intake Plumbix copies the set's criteria onto the change, frozen, and records `criteria_set: {id, owner, task}` on the change and in `change.submitted`. A pull request that names a set and also lists items gets the set, and the gate check says the body's list was ignored. A missing or unknown id leaves the change with the body's criteria (or the submission's) and a note.
- **Kai side** (Kai's own unit): when a task's spec is settled, Kai posts its acceptance criteria as a set and keeps the id with the task, so the pull request or submission can name it.
- **Later, not here**: a URL form for other sources, frozen the same way, with an allowlist of hosts; a Settings rule that a repository requires a set.
- **Rejected** (A43): Plumbix fetching from Kai; editing a set in place after use.

## Acceptance criteria

| # | Criterion | Check |
|---|---|---|
| AC-1 | A set is created, listed and read through the API and the CLI; an edit of a used set is refused with `criteria_set_used`. | api and cli tests |
| AC-2 | An API submission naming a set gets its criteria frozen, with the set's id, owner and task on the change and in `change.submitted`. | api and store tests, the events contract |
| AC-3 | A pull request body naming a set gets its criteria and its own list is ignored, which the gate check says; a pull request cannot create or change a set; an unknown id leaves the body's criteria with a note. | pullrequest tests |
| AC-4 | OpenAPI, events schema, README, the check-runs contract and the change page updated; `make check` green. | `make check` |
