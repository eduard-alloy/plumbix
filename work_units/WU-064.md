# WU-064: Merge strategy settable after registration

**Status**: ✅ Complete (2026-10-30) · **Features**: F-001, F-010 · **Estimate**: short · **Kai**: BEQRCJ (workstream F8QK66, milestone M2 PZTRDV) · **Follows**: WU-066 · **Source**: Chart-AI's first-day follow-up, ask 3

## Goal

`merge_strategy` was fixed at `repo add` (squash by default). It is the strategy of Plumbix's own merges, and with squash GitHub does not recognise a pull request Plumbix lands as merged, so `merger: plumbix` was unusable on a pull-request repository registered with the default.

## Design

- `change.Service.SetRepoMergeStrategy` and `Store.UpdateRepoMergeStrategy`, under the registration rule (`CheckMergeStrategy`: squash, merge, rebase). GitHub's merges of pull requests are not affected.
- `merge_strategy` on `GET`/`PUT /repos/{id}/settings` beside `pull_requests` and `merger`; a body is checked whole before anything is written, so a refused strategy changes nothing. `plumbix repo set --merge-strategy`. OpenAPI `RepoSettings.merge_strategy`.
- Web: a picker on every repository card in place of the plain "squash merge" text, saving through the settings endpoint and reverting on refusal; its title says GitHub's merges are not affected.
