# WU-029: Step caches

**Status**: ✅ Complete (2026-10-18) · **Features**: F-002 · **Estimate**: 1 session · **Kai**: J79KWP · **Decision**: A30

## Goal

A step's dependencies survive between runs. Today every step starts in a fresh container with only the workspace mounted, so Go modules, the Go build cache and npm packages are downloaded on every run; in Plumbix's own pipeline that is most of the time of `build`, `test`, `lint` and `web`. After this unit a plain step lists the container paths it wants kept, and the engine mounts a per-repository directory at each.

## Design

**Pipeline.** `cache:` on a plain step is a list of absolute container paths, at most 8, each cleaned (`/root/.cache/go-build/` becomes `/root/.cache/go-build`), not `/`, not the workspace or under it, no `..`, no duplicates. Not for validators or external steps: a validator judges from evidence in a read-only workspace and must not depend on what an earlier change left behind. The schema and the parser agree; the editor round-trips the field.

**Engine.** For a plain step with caches, the setup hook mounts `<data_dir>/cache/<repo_id>/<slug>` read-write at each path, where the slug is the path with `/` turned into `-` (`go-pkg-mod`) plus a short hash of the path, created `0700` on first use. Caches are per repository and never shared across repositories (A30). Nothing is pruned in this unit: the directory is documented, and deleting it is the reset.

**Editor.** The pipeline model carries `cache`, the YAML writer emits it, and the step panel edits it as a list of paths beside the evidence paths, with the common ones named in the hint.

## Completion

**Delivered**: `steps[].cache` in the parser (`parser.cache`, `MaxCachePaths`) and the schema with valid and invalid examples; `Engine.setupPlain` and `cacheSlug` mounting per-repository directories into plain steps; `cache` in the pipeline editor's API view, OpenAPI, web model, reader, writer, constructors, merge, change list, chips and the step panel ("Caches kept between runs"); ARCHITECTURE (4.2 table, data layout, A30), README, CONSTRAINTS, PROJECT, CONTEXT_LOG.

**Evidence**: the eight refusal cases and `TestCacheListsContainerPathsKeptBetweenRuns` plus the schema examples (pipeline); `TestPlainStepsGetPerRepositoryCacheMounts` (engine: two read-write mounts under `cache/<repo>/`, created, distinct; none for the other steps); the editor model round trip and the inspector test (web). `make check` green.

**Decisions made here** (A30): paths rather than named presets; per repository, never per branch or shared; no pruning in this unit.

**Deferred**: pruning or a size view of caches; a `plumbix cache clear` command or endpoint; a per-step `cache_key` for callers who want isolation per branch.
