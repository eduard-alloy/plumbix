# WU-028: Reviewer profiles and the Settings redesign

**Status**: ✅ Complete (2026-10-18) · **Features**: F-003, F-004 · **Estimate**: 1 session · **Kai**: 185PP4 · **Decision**: A28

## Goal

The operator can define more than one AI reviewer, each with its own provider, endpoint, model and key, and say per validator step which one judges. Today provider, base URL, model and tool policy are four global settings and the key is a global secret name, so one model at a time is possible and the Settings page cannot say which reviewer a repository actually uses. After this unit the page lists reviewer profiles, a step picks one with `reviewer: <name>`, and a second model can be wired into a pipeline beside the first.

## Design

**Profile.** `settings.Reviewer{Name, Kind, BaseURL, Model, Tools, KeySecret, UpdatedAt}`. `Name` is `[a-z0-9][a-z0-9-]{0,31}`. `Kind` is `anthropic` or `openai` (any OpenAI-compatible endpoint). `BaseURL` is for `openai`, validated as today. `Model` is validated as today and may be empty for the kind's default. `Tools` is `read-only` or `full`, used where a reviewer has tools: the external loop's Claude Code, and later the containerised one. `KeySecret` names the secret in the existing store that holds the key; it defaults to `PLUMBIX_REVIEWER_<NAME>_KEY` (upper case, dashes to underscores) and may name any secret, so `ANTHROPIC_API_KEY` can be shared. Profiles live in a table `reviewer_profiles` (migration 0012); the default profile's name is the setting `reviewers.default`.

**Legacy.** On the first start after the upgrade (`Service.EnsureReviewers`, marker `reviewers.migrated`), a profile `default` is created from the old `ai.*` settings: kind from the provider, base URL, model, tools, key secret `ANTHROPIC_API_KEY` or `OPENAI_API_KEY`; the old rows are removed and `default` becomes the default. With no old settings the same profile is created with the built-in values, so a fresh install has one card to edit.

**Binding.** A validator step may carry `reviewer: <name>` (schema and parser; not for plain steps). When the engine prepares a validator step it resolves the profile: the named one, else the default, else none. A name nobody defined fails the step with a log line that says so, so the run ends `needs_human` rather than silently judging with another model.

- Container validator: the profile supplies `PLUMBIX_AI_PROVIDER` (when `openai`), `PLUMBIX_AI_BASE_URL` (when `openai`), `PLUMBIX_AI_MODEL`, and the key from the profile's secret as `ANTHROPIC_API_KEY` or `PLUMBIX_AI_API_KEY` by kind. A secret the step lists itself under the same name wins (`PLUMBIX_` names are reserved to Plumbix, so only the key can be overridden), so a pipeline that already carries its key keeps working unchanged.
- External step: the loop runs Claude Code, so the profile supplies only `Tools` and `Model` to the brief, which also carries the profile's name. An `openai` profile named on an external step is an error; an `openai` default is simply not applied to external steps, which then use the built-in values.

**API.** `GET /api/v1/settings` returns `reviewers` (each with `key_set` and `default`), `default_reviewer`, `guidance` and `secrets`; the `ai_*` fields go. `PUT /api/v1/settings` takes `guidance` and `default_reviewer`. `PUT /api/v1/settings/reviewers/{name}` creates or updates a profile (`kind`, `base_url`, `model`, `tools`, `key_secret`); `DELETE` removes one and clears the default if it was it. Keys are set through the existing write-only secret endpoint under the profile's `key_secret`. The pipeline file view exposes each step's `reviewer`, `external` and `validator`.

**Settings page.** Sections: AI reviewers (one card per profile: kind, model, base URL, tool policy, key with Set/Replace/Remove, Make default, Delete, and which registered repositories' steps use it; an Add form), Review guidance, Git hosts, External reviewers (presence, as today), Other secrets (everything no host and no profile claims). The lead text explains the two ways a review runs and how `reviewer:` picks a profile.

## Acceptance criteria

| # | Criterion | Check |
|---|---|---|
| AC-1 | Profiles are stored, validated, listed, defaulted and removed; the legacy settings migrate once into `default`. | settings tests |

## Completion

**Delivered**: `settings.Reviewer` with validation, `reviewer_profiles` (migration 0012) and the store CRUD, the default profile setting, `EnsureReviewers` (one-time migration of the WU-025 settings, built-in default on a fresh install, wired in `plumbix serve`); `reviewer:` on validator steps in parser and schema with examples; engine `reviewerProfile` and `profileEnv` (provider, base URL, model and the key by kind for container validators; tools, model and name in the brief for external steps; errors for a missing or wrong-kind profile); `PUT/DELETE /api/v1/settings/reviewers/{name}`, settings view with `reviewers` and `default_reviewer`, profile keys listed with their profile's name, OpenAPI; pipeline editor view with `external` and `reviewer`; the Settings page: profile cards (kind, model, base URL with vendor hints, key secret name, tool policy, key row, Make default, Delete, which steps judge with it), an Add form, guidance, hosts, presence, other secrets; README, ARCHITECTURE (API table, 4.3, A28), CONSTRAINTS, PROJECT, CONTEXT_LOG.

**Evidence**: `TestReviewerProfilesAreStoredValidatedAndDefaulted`, `TestLegacyAISettingsBecomeTheDefaultProfileOnce`, `TestDefaultKeySecretName` (settings); the reviewer parse cases and `TestReviewerBindsAValidatorStepToAProfile` plus the schema examples (pipeline); `TestValidatorsGetGuidanceAndModel`, `TestValidatorsGetTheOpenAIProviderAndBaseURL`, `TestAStepNamesItsReviewerProfile`, `TestAnExternalStepTakesToolsAndModelFromItsProfile` (engine); `TestSettingsEndpoints`, `TestReviewerProfileEndpoints`, the external review API test (api); the Settings page tests (web). `make check` green.

**Decisions made here** (A28): profiles in their own table rather than settings rows; the key a secret the profile names, never a field; external steps take only tools and model, from anthropic profiles; a missing profile fails the step rather than falling back.

**Deferred**: advisory validators for comparing models without blocking (Kai task recorded); `plumbix review --profile` to let one loop answer only one profile's reviews; the containerised Claude Code reviewer that would give container validators tools too.
