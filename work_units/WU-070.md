**Status**: ✅ Complete (2026-11-04) · **Features**: F-001, F-010 · **Estimate**: short · **Kai**: G4A0YS (workstream F8QK66, milestone M3 AE14T5) · **Follows**: WU-069 · **Source**: notes the reviews of the WU-059 fix, WU-065, WU-056 and WU-069 left for a unit of their own

## Goal

Five small things the gate's reviewers noted and the units documented instead of taking, closed together so M3 ends clean.

## Design

1. **The merge-order test asserts the order directly.** `TestMergeRecordsBeforeRemovingTheHoldingRef` now reads the commit the record names and checks that, at record time, both the target and the holding ref already point at it, rather than "readable" and "present".
2. **The holding ref is removed when the record fails.** `Engine.Merge` pushes the target, then writes the record; a record that cannot be written left the holding ref on the host for good. It is now deleted best effort before the error returns; the target stays moved and the change approved; a retry is refused as `target_moved` since the run's base is behind, the poller's `bypass_commit` on the head is the record of what happened, and a person resolves it and closes the change, whose code is on the target. `TestFailedMergeRecordRemovesTheHoldingRef` covers the ref, the state and the refused retry.
3. **Migration 0022 on a populated database.** `openUpTo(path, version)` (unexported, `migrateTo`) opens a database with the migrations capped, so `TestMigration0022OnAPopulatedDatabase` registers two repositories, a closed change of one and removes that one at schema 21, then opens normally: the rebuild keeps every row, `pragma_foreign_key_check` is empty, the removed url registers again, a live one does not.
4. **The GitHub report names the App's missing permissions.** `GET /repos/{id}/github` reads the installation's permissions (`GitHubApp.Installation`, `GitHub.AppInstallation`) and lists `permissions` and `missing_permissions` for the repository's shape: checks write and pull requests and contents read always; contents write when Plumbix merges; pull requests write when it also watches pull requests, since WU-056's close fails silently in the log otherwise. The message says what each is for. OpenAPI and the web model carry the fields; the panel shows the message.
5. **The flaky web test.** `ChangePage.test.tsx` read the approval line straight after opening the page; it waits now, as the check above it does (it tripped the web step on WU-069's iteration 3).
