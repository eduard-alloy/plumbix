# WU-063: Auto-merge recorded as the system's act

**Status**: ✅ Complete (2026-10-30) · **Features**: F-010 · **Estimate**: short · **Kai**: QDXWCV (workstream F8QK66, milestone M2 PZTRDV) · **Follows**: WU-062 · **Source**: Chart-AI's first-day follow-up, ask 2

## Goal

A repository with GitHub auto-merge on opens a pull request with auto-merge requested, and GitHub merges the moment `plumbix/gate` goes green. GitHub attributes that merge to the account that requested it, so `change.merged` carried `merged_by: <requester>` and Chart-AI recorded a human act where no person decided anything: the gate did. Without a flag the two are indistinguishable on the wire.

## Design

- **The record** (`change.Merge.AutoMerge`, migration 0019 on `merges`; `engine.ExternalMerge.AutoMerge`; `changeMerged.auto_merge`, additive in `events.schema.json` and OpenAPI): true when GitHub merged on the requester's behalf. `merged_by` stays the requester, so a consumer records the change as the system's act with the requester as operator, and a merge a person pressed as that person's act.
- **Detection** (`Syncer.autoMerged`): the requester is the pull request's `auto_merge.enabled_by` while GitHub still carries the request; GitHub clears that object once merged, so otherwise the issue timeline (`GitHub.PullRequestTimeline`, `GET /issues/{n}/timeline`, paginated) is read and the last of `auto_merge_enabled` and `auto_merge_disabled` wins. The merge is automatic only when the standing requester is the login GitHub names as the merger: a request withdrawn before the merge, or a merge pressed by someone else, is a person's merge. A timeline that cannot be read leaves the merge a person's, and the log says so.
- **Shown**: the change page's merge block gains a "merged by" row: "Plumbix", "GitHub, by <login>", or "GitHub auto-merge, requested by <login>".
- **Not in this unit**: handling the webhook's `auto_merge_enabled` and `auto_merge_disabled` actions (the timeline is the record, read at merge time); Azure DevOps.
