# WU-031: Validator steps say what they run

**Status**: ✅ Complete (2026-10-18) · **Features**: F-003, F-004 · **Estimate**: half a session · **Kai**: 4P8DME

## Goal

Two things the first Grok run made plain. The container AI validator printed nothing for 154 seconds and looked hung; it should say when the request goes out and to whom. And a validator step in the pipeline file does not say what runs: there is no `run:`, only an `image:`, and the owner had to work out that the image's entrypoint is the validator. The file format, the editor and the docs should say so where the reader is looking.

## Design

**Progress.** `aivalidator.Config.Progress` is an optional writer; the validator binary points it at stderr, which the runner streams into the step log while the step runs (WU-027's log panel follows it). Before the request: `ai validator: asking <model> through the Anthropic API (effort <e>): <n> characters of prompt` or `... at <host> (OpenAI-compatible): <n> characters of prompt, response_format json_schema`. On a format fallback: `ai validator: <host> refused response_format json_schema; retrying with json_object`. The final line is unchanged. Nothing secret is ever printed: model, host, sizes and effort only.

**Saying what runs.** The schema's `validator` description, ARCHITECTURE 4.2 (`steps[].image`, `steps[].validator`) and the editor's validator text all say: a validator step runs its image's entrypoint, with no `run`, with the change's inputs mounted read-only at `/plumbix/in` and the workspace at `/workspace`, and must write `/plumbix/out/verdict.json`; Plumbix ships `plumbix-reference-validator` and `plumbix-ai-validator`, built from `validators/` in this repository, and any image honouring section 4.3 can be a validator.
