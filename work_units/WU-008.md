# WU-008: GitHub adapter, host boundary and push detection

**Status**: ✅ Complete (2026-10-16) · **Features**: F-005 · **Estimate**: 6-7 hours

## Goal

Plumbix can fetch private GitHub repositories with a personal access token, notices new pushes by polling, and reacts: a push to a change's source branch revalidates the change, and a push to any other branch starts a plain pipeline run. Host-specific code sits behind one narrow boundary that Azure DevOps will implement next.

## Context

- ARCHITECTURE.md 4.5 (host boundary), A3 (system git), A8 (polling with `git ls-remote`), 5.3 (push without a change). Q12: local-only, so polling, no webhooks. Q13: tokens in a local secrets file, never logged; warn before expiry.
- WU-006 `internal/secrets`, WU-007 engine and `gitops`.
- CONSTRAINTS: never put secrets in process arguments or errors; tests never reach the network.

## Design

**Credentials for git.** Plumbix writes an askpass script to `<data_dir>/git-askpass.sh` (mode `0700`). It contains no secret: it prints `$PLUMBIX_GIT_USER` or `$PLUMBIX_GIT_TOKEN` depending on git's prompt. Those variables are set only in the environment of the git process that needs them. Git also runs with `-c credential.helper=`, so personal credential helpers never interfere or store the token.

**Host boundary (`internal/host`).**
```go
type Host interface {
    Kind() string
    Auth(repo change.Repo) (gitops.Auth, bool) // false: fetch anonymously
    TokenExpiry(ctx context.Context) (time.Time, bool, error)
}
```
- GitHub: user `x-access-token`, token `PLUMBIX_GITHUB_TOKEN` from the secrets file. Without a token, public repos still work.
- Token expiry: GitHub returns it in the `github-authentication-token-expiration` header of an authenticated API call. The poller checks once a day and logs a warning within 7 days of expiry. Showing it as an alert comes with alerts in WU-010.

**Branch heads.** A `branch_heads` table remembers the last head seen per repo and branch. Runs gain a `branch` column.

**Poller (`internal/poller`).** Every `poller.interval` (default `30s`), for each repo:
1. `git ls-remote --heads` with the host's credentials.
2. The first poll of a repo only records the heads, so registering a repo doesn't trigger a flood of runs.
3. For each new or moved branch: if a change that isn't merged or closed uses it as its source branch, and that change's latest run isn't already on this commit, revalidate the change. Otherwise start a plain run for the branch.
4. Deleted branches are forgotten. A failing repo is logged and doesn't stop the others.

**Plain runs (engine `RunBranch`).** They run the branch's pipeline without its validator steps, since there is no intent to judge. They have no outcome and touch no change.

**API and CLI.** `GET /api/v1/repos/{id}/runs` lists a repo's runs, newest first, with an optional `branch` filter. CLI: `plumbix repo runs <id> [--branch b]`.

**Config.** `poller.interval` (default `30s`, at least `5s`) and `poller.enabled` (default `true`).

## Acceptance criteria

- **AC-1**: Against a local git HTTP server that requires basic auth, a fetch with the right token works, and a fetch without it or with a wrong one fails. Errors never contain the token, and the token never appears in git's arguments.
- **AC-2**: `ListHeads` returns every branch head of a remote, with auth.
- **AC-3**: The GitHub adapter returns credentials from the secrets, works without a token, and reads token expiry from a fake API.
- **AC-4**: Poller: the first poll records only; a push to a change's branch revalidates it; a push to another branch starts a plain run; an unchanged head does nothing; a change already validated at that commit isn't revalidated; deleted branches are forgotten; one failing repo doesn't block the rest.
- **AC-5**: A plain run executes the pipeline without validators, finishes without an outcome, and changes no change state.
- **AC-6**: Repo runs are listed through the API and CLI, matching the OpenAPI schemas.
- **AC-7**: `make check` and `make integration` pass.

## Steps (test first for each)

**Decisions**
- Tokens reach git only through the environment of the git process, via an askpass script that holds no secret. Personal credential helpers are switched off with `-c credential.helper=`, so a token is never stored in the user's keychain.
- The poller compares heads with what it saw last (stored, so restarts don't miss or repeat pushes). The first poll of a repo only records.
- Plain runs share the launch path with change runs: a new push to the same branch cancels the previous plain run.
- Token expiry warnings go to the log for now. Alerts arrive with WU-010.

**Problems hit**
- `end()` crashed on plain runs, which have no combined result. Caught by the first `RunBranch` test.
- `TestRealContainersRunInParallel` asserted a wall-clock limit and failed under the full parallel suite. It now checks that the two steps overlapped in time, which doesn't depend on how fast Docker is.
