# WU-055: Pull-request API calls as the App; gating settable on a registered repository

**Status**: ✅ Complete (2026-10-28) · **Features**: F-010 · **Estimate**: half a session · **Kai**: XW915Y (workstream F8QK66, milestone M2 PZTRDV) · **Follows**: WU-054

## Goal

Make the pull-request gate of WU-054 usable on a real repository, Plumbix's own first. Two things stood in the way, both found while setting the owner's GitHub App up:

1. GitHub creates check runs only for a GitHub App. WU-054 picked the API token the way `Auth` picks git credentials, the personal token first, so a repository with both a PAT and an installed App (this one) would have posted no check run at all.
2. `pull_requests` and `merger` could only be given at registration. The owner's repository is registered already, and there was no endpoint or command to turn them on.

## Design

- **Token choice** (`internal/host/github_api.go`, `apiToken`): with an App configured, a REST call under `/repos/{owner}/{repo}` mints the App's installation token for the repository and uses it; when the mint fails (the App is not installed there, or GitHub refuses the JWT) the repository's own token or the host token serves the call, and with neither the error names the App's failure. Git credentials (`Auth`) are unchanged: the token first, the App as the fallback, since a PAT with contents write pushes the merges for `merger: plumbix` repositories.
- **App check** (`GitHub.AppCheck`): verifies the App's id and key against GitHub whatever token is set; says when no App is configured or the configured one is unusable, without the key. The Settings secret check of `PLUMBIX_GITHUB_APP_ID` and `PLUMBIX_GITHUB_APP_KEY` calls it instead of the token check.
- **Settable gating** (`change.Service.SetRepoMerging`): the registration rules, lifted into `normalizeMerging` so both paths share them (pull requests on GitHub only, `merger: github` on GitHub only, an empty merger takes the default for the new `pull_requests` value). `Store.UpdateRepoMerging` joins the store interface. `PUT /api/v1/repos/{id}/settings` takes `pull_requests` and `merger` beside `guidance`; a field left out of the body stays as it is, and the response (and `GET`) carries all of them. `plumbix repo set <id> [--pull-requests[=false]] [--merger plumbix|github]` sends only the flags given. The repository card shows "Pull requests · GitHub merges" or "Pull requests · Plumbix merges" for a gated repository.
- **Not in this unit**: a switch on the repository card to flip the setting in the browser (the API and the CLI do it); Azure DevOps.

**Iteration 1** (`approved`; three minor findings taken, one left): the App secret check called `AppCheck` twice and could call `.Error()` on a nil error; it runs once. The settings update applies the guidance before the merging, so a body refused for its guidance changes nothing.
