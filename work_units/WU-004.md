# WU-004: Change contract and storage

**Status**: ✅ Complete (2026-10-16) · **Features**: F-001 · **Estimate**: 5-6 hours

## Goal

A client can register a repo and submit a change with its intent and acceptance criteria through the public API or the CLI. Plumbix validates it, stores it in SQLite and returns it. Changes can be listed, read and closed. The API output is checked against the OpenAPI schemas by a contract test.

## Contract

**Repo** `POST /api/v1/repos`
- `host`: `github` or `azuredevops`. Required.
- `url`: HTTPS clone URL matching the host. GitHub `https://github.com/<owner>/<repo>[.git]`. Azure DevOps `https://dev.azure.com/<org>/<project>/_git/<repo>` or `https://<org>.visualstudio.com/<project>/_git/<repo>`. Required, unique.
- `protected_branches`: list of branch names. Default `["main"]`.
- `merge_strategy`: `squash` (default), `merge` or `rebase`.
- Response 201 with `id` (`r_` plus 12 characters) and `created_at`. A URL that is already registered gets 409 `conflict`.

**Change** `POST /api/v1/changes`
- `repo_id`, `source_branch`, `target_branch`, `title` (at most 200 characters), `intent`: required.
- `acceptance_criteria`: at least one. Each has `text` (required), optional `id` (`AC-<n>`, unique; assigned in order when missing) and optional `check`, which is exactly one of `{"steps": [...]}` (step names) or `{"command": "..."}`.
- `constraints`: optional list of strings. `submitted_by`: optional string.
- Branch names follow git's ref rules. Source and target must differ.
- Response 201 with `id` (`c_` plus 12 characters), `state: "open"`, `created_at`, `updated_at`.
- Unknown repo gets 404. Another change still open on the same repo and source branch gets 409 `conflict`.

**Reading and closing**
- `GET /api/v1/repos`, `GET /api/v1/changes?repo_id=&state=`, `GET /api/v1/changes/{id}`.
- `POST /api/v1/changes/{id}/close`: allowed unless the change is already `merged` or `closed`, which gets 409 `invalid_state`.

**Errors**: invalid JSON, unknown fields or field problems get 400 `invalid_request` with `details.problems: [{field, message}]` listing every problem. Bodies over 1 MiB get 413.

## Storage

- `<data_dir>/plumbix.db`, SQLite through `modernc.org/sqlite`, WAL mode, foreign keys on, busy timeout set.
- Embedded, numbered SQL migrations recorded in a `schema_migrations` table.
- A partial unique index enforces one open change per repo and source branch.

## CLI

All commands talk to the running server through the public API with the token from the data directory, and print JSON.
- `plumbix repo add --host <h> --url <u> [--protected <b>]... [--merge-strategy <s>]`
- `plumbix repo list`
- `plumbix submit -f <change.json>` (`-f -` reads standard input)
- `plumbix change list [--repo <id>] [--state <s>]`, `plumbix change show <id>`, `plumbix change close <id>`

## Acceptance criteria

- **AC-1**: A repo can be registered and listed. Host and URL mismatches, bad strategies and duplicates are rejected with the documented codes.
- **AC-2**: A valid change is stored and returned with state `open`, assigned criterion IDs and timestamps. It survives a server restart.
- **AC-3**: Every field rule has a test, and a request with several problems lists all of them.
- **AC-4**: A second open change on the same repo and source branch gets 409. After closing the first, a new one is accepted.
- **AC-5**: List filters by repo and state. Show returns one change. Close follows the state rule.
- **AC-6**: Contract test: real responses for repo, change, change list and errors validate against the OpenAPI component schemas.
- **AC-7**: The CLI can do all of the above against a running server, using the token automatically.
- **AC-8**: `make check` passes. No TODOs or debug prints.

## Steps (test first for each)

1. Store: open, migrate, pragmas, repo and change persistence, the open-change index.
2. Validation: repo and change rules, problem lists, git ref names, criterion IDs.
3. Service: submit, get, list, close with state rules and error kinds.
4. API handlers and error mapping.

**Decisions**
- The `change` package owns the model and the `Store` interface. `store` implements it, so the rules never depend on SQLite.
- IDs are a prefix plus 12 random base32 characters (`r_`, `c_`), not counters. Clients can't guess or enumerate them.
- List endpoints return an object (`{"repos": [...]}`, `{"changes": [...]}`) so fields such as paging can be added without breaking clients.
- An unknown repo on submit is a 404, not a field problem, matching the spec.
- Missing criterion IDs take the smallest unused `AC-<n>`, so mixed explicit and missing IDs never collide.
- Submitted text has upper limits (title 200, intent 20,000, criterion text 2,000, at most 50 criteria) to keep requests and storage bounded.
- `api.NewHandler` now takes a `Deps` struct, because it needs more than two dependencies.
- CLI flags work before or after positional arguments, and every command prints JSON for agents.

**Problems hit**
- `TestServeStartsAndStops` hung for 5 seconds, but only after `TestCLIFlow` ran. A goroutine dump showed `Shutdown` waiting on a connection. Go's shared HTTP transport can leave a spare connection that never sends a request, and `Shutdown` waits up to 5 seconds for those. Tests now close idle client connections before stopping a server. Six repeated runs passed.

**Notes**
- The database file is created with the default umask (0644). It lives inside the data directory, which Plumbix creates with mode 0700.
