# WU-022: Update from main

**Status**: ✅ Complete (2026-10-18) · **Features**: F-002, F-004 · **Estimate**: 5 hours · **Kai**: C62QQ5

## Goal

A change whose branch Plumbix created (the pipeline editor's) can be brought up to date with its target branch from the change page, the API and the CLI, so a `target_moved` refusal never needs a terminal. Opened by the first editor-made change on Plumbix itself: it fell behind main while it waited for approval, and the only remedy was `git merge` and `git push` by hand.

## Context

- A15: merge lands exactly the validated tree, so a change whose base is no longer the target's head is refused with `target_moved`. The fix is a new head that contains the target, validated again.
- A22: the editor's branches are Plumbix's own; Plumbix never writes a protected branch and never forces a push. Refreshing such a branch is Plumbix editing its own work. An agent's branch stays the agent's: Plumbix does not push merge commits onto branches it did not create.
- A21 and A23: a refresh is a person's action, so it starts a run even on a sticky state; the new run clears a standing approval, as any new run does.

## Design

**Ownership.** `Change.plumbix_branch` (migration 0010) is set by the editor's propose endpoint and cannot be set through `POST /changes`. The refresh checks git as well: every first-parent commit between the merge base and the branch head must be authored by Plumbix, otherwise `not_plumbix_branch`.

**Refresh.** `Engine.Refresh(id)`: the change is neither final nor running; fetch; if the branch already contains the target's head, `already_current`; `Mirror.MergeBranches(head, target)` writes the merged tree with `git merge-tree --write-tree` and commits it with Plumbix as author and both heads as parents (`merge_conflict` with the conflicting paths when the trees do not merge); `Mirror.Push` moves the branch from the old head to the merge commit under a lease; the event `change.refreshed` `{from_head, head, target_head}` is recorded; `Engine.Validate` starts the new iteration. A poller run that arrives first is accepted as the same outcome.

**API and CLI.** `POST /api/v1/changes/{id}/refresh` → 200 `Change` (404; 409 `invalid_state`, `already_current`, `not_plumbix_branch`, `merge_conflict`, `push_rejected`, `push_denied`). `plumbix change refresh <id>`.

**Web.** On a change with `plumbix_branch`, not final and not running, the actions show "Update from `<target>`"; the `target_moved` refusal offers that action instead of a command to copy. The result notice says the branch was updated and the change is validating, or why not.

**Decisions made here** (A24): only Plumbix's own branches, checked by flag and by git; a merge commit rather than a rebase; the approval is not carried across a refresh, a person approves again; a poller run that reaches the push first is accepted as the same outcome.

**Deferred**: refreshing an agent's branch on the agent's behalf (would need the agent's consent in the submission); carrying an approval across a refresh with an unchanged diff.
