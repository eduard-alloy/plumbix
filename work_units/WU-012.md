# WU-012: Self-hosting acceptance

**Status**: 🔄 In progress (2026-10-16) · **Features**: all of milestone 1 · **Estimate**: 3 hours

## Goal

Milestone 1 is done when Plumbix validates its own changes through its public API on GitHub. This unit adds Plumbix's own pipeline, runs a real local server against the real repository, pushes a real change through submit, verdict and merge, and records the evidence. From this unit on, every change to Plumbix goes through Plumbix.

## Context

- PROJECT.md milestone 1 success criteria. ARCHITECTURE A9 (required validators come from the target's pipeline; `.plumbix/` edits need a human), A12 (AI validator approved, deterministic validator must also approve), A15 (merge rule).
- WU-008 to WU-010 (GitHub, poller, merge, bypass alerts), WU-016 and WU-011 (browser).
- Secrets: `PLUMBIX_GITHUB_TOKEN` and `ANTHROPIC_API_KEY` in the repository's `.env`, pointed at from `~/.plumbix/config.yaml`.

## Design

**Pipeline** (`.plumbix/pipeline.yaml`): `build`, `test`, `lint` on `golang:1.27` and `web` on `node:24-alpine`, independent so they run in parallel; `validate` (reference validator) and `ai-review` (AI validator with `ANTHROPIC_API_KEY`) after all four. Go module and npm downloads happen inside each fresh container; a run takes a few minutes. Criteria use step checks: the reference validator image has no Go toolchain, so command checks are not used here.

**Bootstrap.** The target branch must carry the pipeline before a change can be validated, and a change that adds `.plumbix/` needs a human by A9, so the pipeline file lands on `main` by a direct push, once. The poller sees that commit arrive without a verdict and raises a `bypass_commit` alert, which doubles as the acceptance check for bypass detection; it is resolved with this unit.

**Procedure.**
1. `~/.plumbix/config.yaml` points `secrets_file` at the repository's `.env`; `make images` builds the validator images; `plumbix serve` runs from the built binary.
2. `plumbix repo add --host github --url https://github.com/eduard-alloy/plumbix.git --protected main`. Wait for the first poll.
3. Push the pipeline commit to `main`. Confirm the alert, resolve it.
4. Branch `wu-012-self-hosting` with this unit's documentation; `plumbix submit` with the intent and criteria checked by steps. Watch the run (steps in parallel, verdict from both validators), then `plumbix change merge`.
5. Record change id, run id, verdict and merge commit in this file through a second change, which goes through Plumbix the same way.

## Acceptance criteria

- **AC-1**: `.plumbix/pipeline.yaml` passes `plumbix pipelines check` and runs all four build steps in parallel on a real run.
- **AC-2**: A change to this repository, submitted through the public API, gets a verdict from the reference validator and the AI validator, and is merged by Plumbix onto `main` with the validated tree.
- **AC-3**: The bootstrap push to `main` raised a `bypass_commit` alert naming the commit.
- **AC-4**: Pushes are detected by polling: a push to the change's branch starts a new iteration without any manual call.
- **AC-5**: The milestone 1 criteria in PROJECT.md are each ticked with a pointer to the evidence.
- **AC-6**: `make check` and `make integration` pass.
