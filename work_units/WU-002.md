# WU-002: Pipeline format v0

**Status**: ✅ Complete (2026-10-16) · **Features**: F-002 · **Estimate**: 3-4 hours

## Goal

Plumbix can read a `.plumbix/pipeline.yaml`, reject anything invalid with every problem listed by path and line, and produce a checked step graph for the scheduler. The format is published as a JSON Schema, and a contract test keeps the schema and the parser in agreement.

## Context

- ARCHITECTURE.md 4.2 (pipeline file), A7 (contracts are the source of truth, checked by tests).
- DISCOVERY Q08: minimal, strict, learnable in ten minutes. Unknown fields are errors.
- WU-001: `go.yaml.in/yaml/v3` is already a dependency. API errors use the shared error shape.

## Rules (format version 1)

| Field | Rule |
|-------|------|
| `version` | Required. Integer `1`. |
| `steps` | Required. Non-empty list. |
| `steps[].name` | Required. Lowercase letters, digits and dashes, starts and ends with a letter or digit, at most 63 characters. Unique. |
| `steps[].image` | Required. Non-empty, no whitespace. |
| `steps[].run` | Required and non-empty for normal steps. Optional for validators, which may rely on the image's entrypoint. |
| `steps[].needs` | Optional list of other step names. No unknown names, no self-reference, no duplicates, no cycles. A step cannot need a validator, because verdicts are final outputs. |
| `steps[].env` | Optional map of string to string. Values must be strings in YAML. Keys match `[A-Za-z_][A-Za-z0-9_]*` and must not start with `PLUMBIX_`, which is reserved. |
| `steps[].secrets` | Optional list of secret names, same key rules, unique, not also in `env`. |
| `steps[].artifacts` | Optional list of workspace-relative paths. No absolute paths, no `..` segments. |
| `steps[].timeout` | Optional duration such as `90s` or `10m`. Above zero and at most `24h`. |
| `steps[].validator` | Optional boolean. |

Structure and per-field rules are in the JSON Schema. Rules across fields (unique names, references, cycles, env and secret overlap, validators not needed by other steps) are enforced by the parser and listed in the schema's description.

## Scope

**In**
- `contracts/pipeline.schema.json` (JSON Schema 2020-12).
- `internal/pipeline`: `Parse` returning a `Pipeline` or a validation error that lists every problem with path, line and message. `Pipeline.Order()` returns a deterministic dependency order.
- Contract test over example files in `internal/pipeline/testdata/`: valid files pass both schema and parser, structurally invalid files fail both, and cross-field invalid files pass the schema but fail the parser.
- `POST /api/v1/pipelines/check`: body is the pipeline YAML. Returns 200 with `{"valid": true, "order": [...]}` or `{"valid": false, "errors": [...]}`. Bodies over 1 MiB get 413.
- OpenAPI updated.

**Out**
- Running anything (WU-003). Reading the file from a repo (WU-004 onward). A CLI for checks.

## Acceptance criteria

- **AC-1**: The example pipeline from ARCHITECTURE.md 4.2 parses, and its order lists `test` and `lint` before `validate` and `ai-review`.
- **AC-2**: Each rule in the table has a test with a file that breaks it, and the error names the path and line.
- **AC-3**: A file with several problems reports all of them, not just the first.
- **AC-4**: The contract test passes: schema and parser agree on every example file as described in Scope.
- **AC-5**: The check endpoint returns the documented shapes for a valid file, an invalid file and an oversized body.
- **AC-6**: `make check` passes. No TODOs or debug prints.

## Steps (test first for each)

1. Valid example parses into a `Pipeline` with the right fields.
2. Structural rules: version, steps, required fields, types, unknown fields, with line numbers.
3. Field rules: name, image, env keys, secrets, artifacts, timeout.
4. Cross-field rules: unique names, needs references, self, duplicates, cycles, validator not needed, env and secret overlap.
5. Dependency order.
6. JSON Schema and the contract test.
7. Check endpoint and OpenAPI.

**Decisions**
- The parser walks the YAML node tree instead of decoding into structs. That gives exact paths and lines, strict types (an unquoted `8080` in `env` is rejected), and every problem in one pass.
- `Order()` groups steps into dependency levels and keeps file order inside each level. The scheduler can start each level's steps in parallel.
- An invalid pipeline returns HTTP 200 with `valid: false`. The request succeeded; the file did not.
- `github.com/santhosh-tekuri/jsonschema/v6` validates JSON Schema 2020-12 in tests. Later contract tests (verdict, events, API) reuse it.

**Discoveries** (added to CONSTRAINTS.md)
- Go's build cache, once written outside the sandbox, can't be read inside it. Go commands now run outside the sandbox consistently.
