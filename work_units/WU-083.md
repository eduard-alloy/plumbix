# WU-083: A pull request whose head Plumbix merged through an API-submitted change is not reopened from its body

**Status**: ✅ Complete (2026-11-06) · **Features**: F-010 · **Estimate**: one session · **Kai**: SAZARN (workstream F8QK66, milestone P41048) · **Follows**: WU-082 · **Source**: Chart-AI's third-day ask (A53)

## Goal

A pull request whose tree Plumbix already merged never becomes another change, whether the merged change mirrored the pull request or was submitted through the API on its branch.

## What is wrong today

On 2026-11-06 Chart-AI closed a pull request's change to amend a frozen criterion (A43 keeps criteria frozen at intake, so close and resubmit is the way), resubmitted the same head through `submit_change` with the amended criterion, and Plumbix approved and merged it. Nine seconds later the sync opened a third change from the still-open pull request, with the old criterion from the body, which failed on exactly that point and cost an ai-review iteration for a verdict contradicting the merged one on identical code.

The WU-056 suppression ("a pull request Plumbix merged never gets a second change") asks `LastChangeByPullRequest`, keyed by pull request number. A change submitted through the API carries no number, so the merged change was invisible to the sync, and the merge-time close of the pull request, which also goes by the change's number, never ran.

## Design

1. **`Store.LastChangeOnBranch(repo, source, target)`**: the newest change from a branch to a target, whatever its state and origin; `ErrNotFound` when there never was one.
2. **The sync's `landedByPlumbix`** keeps its first question (the pull request's own last change, merged by Plumbix) and asks a second: the newest change on the pull request's branch and target is one Plumbix merged (its own strategy, no login as the merger) and the head that merge validated is the pull request's head. Then the pull request has landed. A head pushed since is a tree nobody validated and gets a change as before.
3. **`closeLanded`** comments when the change is not the pull request's own, naming the head, the landing commit and the change, since nothing on the pull request says so yet; the moved-head comment and the silent close of a pull request already commented on stay as they were.
4. **Kept as is (A53)**: A43. The window between the close and the resubmission, in which the sync may open a change from the body, is accepted; the resubmission then fails with `conflict` and the client closes the sync's change. Rejected: amendable criteria per iteration; a `superseded_by` link honoured by the sync; writing the client's criteria back to the body; attaching the pull request number to a `submit_change` on its branch (the sync would then follow the body on every pass and overwrite the client's criteria with the stale ones).
