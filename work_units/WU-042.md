# WU-042: Publish a local folder to a new repository online

**Status**: ✅ Complete (2026-10-19) · **Features**: F-001, F-004 · **Estimate**: 1 session · **Kai**: X6EBY6 · **Decision**: A35

## Goal

The third import way the owner asked for: a folder on this machine with commits but no remote becomes a repository on GitHub or Azure DevOps, pushed and registered with Plumbix, from the Repositories page.

## Design

**Creating online.** `host.GitHub.CreateRepository(token, owner, name, private)` creates an empty repository under the token's account (owner empty or the account's login) or an organisation; `host.AzureDevOps.CreateRepository(token, org, project, name)` creates one in a project. A token given for this repository wins over the host token; it travels only in the Authorization header and is never echoed. Errors say what the host refused: a rejected token, a missing permission, a taken name.

**Pushing.** `gitops.Publish(path, url, auth)` refuses a folder that has a remote or no commits, adds `origin` with the HTTPS URL (no credentials in it), pushes every branch without forcing, and makes the checked-out branch track its copy. This is the one import that changes the local folder, and the page says so.

**API.** `POST /api/v1/repos/publish {path, host, owner, project, name, private, token}` validates the path (inside the home directory, the top of a working tree), the host (GitHub or Azure DevOps only), the names, then creates and pushes, answering `{url, host, default_branch, pushed}`. `create_failed` means nothing changed; `push_failed` means the repository exists online and the folder has origin, and says so. Registration and the token stay the page's next calls, as in WU-041.

**Page.** A third tab, Publish a folder: a folder and Inspect; a folder with a remote is sent to the Local folder tab, one without gets the host, owner or organisation and project, name (the folder's), private for GitHub, protected branch, merge and token choice. Create and push reports Created, Pushed, then Registered, Token stored, Access checked. The Local folder tab offers Publish it instead for a folder without a remote.

**Review notes from WU-041.** `InspectFolder` accepts only the top of a working tree; the browser's remote rules use the server's exact SSH patterns and have their own test with the server's cases; a comment notes that git also refuses a non-empty clone destination.
