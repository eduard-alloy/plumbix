# WU-024: Plumbix MCP server

**Status**: ✅ Complete (2026-10-18) · **Features**: F-001, F-003, F-004 · **Estimate**: 1 session · **Kai**: PGTW5K

## Goal

An agent session, Claude Code first, can drive Plumbix from inside: submit a change, follow it to a verdict, read what the validators said, approve, merge, refresh, and act as an external reviewer, all through MCP tools instead of shelling out to the CLI. The server is `plumbix mcp`, a stdio server in the same binary, speaking to the Plumbix API with the same token and config as every client command.

## Design

**Transport and identity.** `plumbix mcp [--name <agent>]` runs an MCP server over stdio with the official Go SDK. Each process mints a session identity `mcp:<name>:<6 hex>` (name defaults to `agent`). Changes submitted through the session carry it as `submitted_by`, and reviews are claimed under it as the reviewer name, so the existing rule that nobody reviews their own change holds for the session without a server change: the submitter and the reviewer are the same string. A later server-side identity can replace the string; the tools keep their shape.

**Tools.** Thin wrappers over the API, typed inputs, structured outputs:

| Tool | Does |
|---|---|
| `list_repos` | Registered repositories. |
| `submit_change` | `POST /changes` with repo, branches, title, intent, criteria, constraints; validation starts; returns the change. |
| `get_change`, `list_changes` | A change, or changes filtered by repository and state. |
| `get_runs`, `get_step_log` | A change's runs with verdicts; one step's log. |
| `wait_for_verdict` | Follows the event stream for a change until a verdict, a final state or a timeout (at most 55 minutes, long enough for a pipeline), and returns the verdict with the change's state. |
| `approve_change`, `merge_change`, `refresh_change`, `close_change`, `validate_change` | The person's actions, with the same refusals the API gives. |
| `next_review`, `post_verdict` | The external reviewer loop from inside a session: claim the next brief (never the session's own change) and post the verdict; the brief's prompt tells the agent what to judge. |
| `list_alerts`, `resolve_alert` | Bypass commits, token warnings, missing reviewers. |

Errors come back as tool errors with the API's code and message, so the agent sees `target_moved` or `not_plumbix_branch` as text it can act on.

**Install.** The README shows `claude mcp add plumbix -- plumbix mcp`. No file is written by Plumbix.

## Completion

**Delivered**: `internal/mcpserver` (identity, sixteen tools, API wrapper that turns refusals into tool errors with the API's code, `wait_for_verdict` over the event stream, `next_review` through the client's long poll); `plumbix mcp [--name]`; the official Go SDK as a dependency; README, ARCHITECTURE (components), CONSTRAINTS, PROJECT, CONTEXT_LOG. Also carried: two notes from the verdict-line review (a schema example with `usage.turns` and `usage.cost_usd`, the verdict line kept to one line).

**Evidence**: `TestToolsWrapTheAPIUnderTheSessionIdentity` (tool list, `submitted_by` forced to the identity, a 409 as a tool error carrying `invalid_state`, a claim polled as the identity) and `TestWaitForVerdictFollowsTheRunningIteration` (replayed old verdict ignored, running iteration's verdict returned, timeout answered) with the SDK's in-memory transports against a fake API; CLI usage check. `make check` green.

**Decisions made here**: identity is a string the session mints, used on both sides of the own-change rule, rather than a new server concept; tools return the API's JSON as structured content instead of curated shapes, so they never lag behind the API; no file is written for the client, the README shows the Claude Code command.

**Deferred**: server-side session identity with its own token; MCP resources for logs and diffs; prompts that package the review brief as an MCP prompt.
