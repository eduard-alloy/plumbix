# WU-023: External validator step and `plumbix review --watch`

**Status**: 🔄 In progress (2026-10-18) · **Features**: F-003, F-004 · **Estimate**: 2 sessions · **Kai**: 2DAEKX

## Goal

A validator step can be satisfied by a reviewer outside the pipeline: Plumbix publishes a review brief and waits for a verdict posted back. A Claude Code session, or `plumbix review --watch` on any machine with Claude Code installed, pulls the next brief, reviews with its own tools and authentication, and posts the verdict. People use the Claude they already have, and the server stays the author of the prompt and the gate on the verdict (A26).

## Context

- A12 and Q07: AI lives in validator steps, never in the core. The external step keeps that: the core publishes a prompt and checks a verdict; the model call happens wherever the reviewer runs.
- Claude Code cannot be called back by an MCP server (no sampling support), so the direction is pull: the reviewer asks Plumbix for work.
- A verdict that never arrives, or does not pass the checks every verdict passes, is a validator error: the change goes to a person, never to approval.

## Design

**Pipeline.** A validator step with `external: true` has no `image`, `run`, `env` or `secrets`; `timeout` bounds the wait (default 1 hour). Example: `- {name: ai-review, validator: true, external: true, needs: [build, test], timeout: 2h}`.

**Run.** When the scheduler reaches an external step, the engine builds the review brief from the same inputs a container validator gets: the AI validator's prompt (system and user parts, repository content in the untrusted block), the verdict JSON schema with the change's criterion ids, head, base, iteration, repository URL, and the operator's tool policy and model. It stores a `reviews` row (status `pending`, a one-time token kept as a hash, an expiry at the step's timeout, the brief), emits `review.requested`, writes a line to the step log, and waits. When a verdict arrives the engine writes it as the step's `verdict.json` and the step succeeds; the usual verdict reading and checks follow. At the timeout the review is `expired` and the step is `timed_out`, a validator error.

**Claiming.** `GET /api/v1/reviews/next?reviewer=<name>&repo_id=<id>&wait=<seconds>` long-polls up to the wait (at most 55 s) and atomically claims the oldest pending review the reviewer may take, emitting `review.claimed`. A reviewer never receives a change it submitted itself (`submitted_by` equals the reviewer name; the MCP server of WU-024 tightens this to session identity). The response is the brief with the token; 204 when nothing is pending. `POST /api/v1/reviews/{id}/verdict` `{token, verdict}` accepts the verdict once: the token must match, the review must be pending or claimed and not expired, and the verdict must pass the same checks as a file from a container (400 with the problems otherwise, 409 for a wrong token or a review already answered or expired).

**Settings.** `ai_tools`: `read-only` (default) or `full`. It travels in the brief as `tools`; `plumbix review` and the later container image obey it. The web Settings page shows it as a toggle.

**CLI.** `plumbix review --watch [--repo <id>] [--reviewer <name>] [--once] [--model <m>] [--tools read-only|full]`: long-polls `next`, checks the head out in a worktree under `<data_dir>/review/<repo>` with the user's own git access, runs `claude -p` with the brief's system prompt, user prompt and schema (`--output-format json --json-schema`, `--restricted` unless tools are full, `--no-session-persistence`, a turn and budget cap), posts the verdict, prints one line per review, and keeps going.

**Events and contracts.** `review.requested` `{run_id, step, review_id, expires_at}` and `review.claimed` `{review_id, reviewer}`; OpenAPI paths and the `ReviewBrief` schema; `external` in `pipeline.schema.json`.

## Acceptance criteria

| # | Criterion | Check |
|---|---|---|
| AC-1 | The parser accepts `external: true` on a validator step without an image and refuses it with `image`, `run`, `secrets` or on a plain step. | pipeline test |
| AC-2 | An external step publishes a brief, succeeds with the posted verdict as its own, and times out into a validator error when none arrives; the brief carries the AI validator's prompt and schema. | scheduler and engine tests |
| AC-3 | `next` claims atomically, long-polls, skips the reviewer's own changes and answers 204 when idle; `verdict` accepts once with the right token and refuses wrong tokens, repeats, expiries and invalid verdicts with the right codes. | store and api tests |
| AC-4 | `ai_tools` round-trips through settings and the brief; the events are emitted and in the schema. | settings, store, api tests |
| AC-5 | `plumbix review --watch` turns a brief into a `claude -p` run and posts its output; a fake `claude` on the PATH proves it without a model. | cli test |
| AC-6 | `make check` passes; the web Settings page has the tools toggle. | web tests |
