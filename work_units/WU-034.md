# WU-034: Reasoning effort for API reviewers

**Status**: ✅ Complete (2026-10-18) · **Kai**: 173C9H · **Features**: F-003, F-004 · **Estimate**: 1 session

## Goal

A review by Grok 4.7 took 257 s and then 399 s in a measured probe, almost all of it hidden reasoning: 30,134 reasoning tokens before a 344-token answer. The same request with `reasoning_effort: low` took 110 s and 6,927 reasoning tokens. The OpenAI-compatible path sent no effort at all, and the validator logged only the visible tokens, so the time could not explain itself. After this unit the operator sets an effort per API reviewer profile, a validator step can override it in the pipeline, the validator sends it and reports the reasoning tokens.

## Design

**Profile.** `settings.Reviewer.Effort` for API kinds: `low`, `medium`, `high`, or empty for the vendor's default; refused on `claude-code`. Column `effort` on `reviewer_profiles` (migration 0014). The card shows it as a select.

**Step.** `effort:` on a validator step, same values, overrides the profile. Plain steps refuse it. The pipeline editor's validator panel shows a Reviewer select (the profiles from Settings, or the default) and an Effort select, writes `reviewer:` and `effort:`, and the card chips show both.

**Engine.** `profileEnv` sets `PLUMBIX_AI_EFFORT` from the step's `effort`, else the profile's; nothing when neither is set, so the validator keeps its own default.

**Validator.** `aivalidator.Config.EffortSet` says the operator chose. On the Anthropic path the effort is sent as today. On the OpenAI-compatible path `reasoning_effort` is sent when set (`xhigh` and `max` become `high`); a vendor that answers 400 naming it gets the request again without it, with a progress line. The response's `completion_tokens_details.reasoning_tokens` becomes `Usage.ReasoningTokens` (`reasoning_tokens` in the verdict contract), printed in the validator's final line and the step's verdict line.
