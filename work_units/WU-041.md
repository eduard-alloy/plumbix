# WU-041: Import a repository from a local folder, or clone a remote

**Status**: ✅ Complete (2026-10-19) · **Features**: F-001, F-004 · **Estimate**: 1 session · **Kai**: 2XAXTA · **Decision**: A35

## Goal

Repositories are registered only with `plumbix repo add --host … --url …`. The owner wants an Import button on the Repositories page that brings in a repository two ways: from a local folder that already has a remote, and by cloning a remote into a local folder. A third way, publishing a folder that has no remote, is WU-042.

## Design

**Remote detection.** `change.DetectRemote(remote)` names the host and the URL Plumbix registers: GitHub and Azure DevOps HTTPS URLs as they are (user info dropped), their SSH forms (`git@github.com:o/r.git`, `ssh://git@github.com/o/r.git`, `git@ssh.dev.azure.com:v3/org/project/repo`) turned into HTTPS so the token works, any other `ssh://`, `user@host:path`, `file://` or absolute path as plain git; other HTTPS hosts are refused by name.

**Folders.** `gitops.InspectFolder(path)` reads a working tree through git only: the `origin` remote (else the first remote), the default branch (`origin/HEAD`, else the checked-out branch), and whether `.plumbix/pipeline.yaml` is in `HEAD`. `gitops.Clone(url, dest, auth, askpass)` clones with credentials in the process environment only, never forcing, into a folder that does not exist or is empty.

**Paths.** Every path comes from the person and is resolved before use: `~` expanded, made absolute, symlinks resolved on the part that exists, and it must lie inside the import root, the server user's home directory (`Deps.ImportRoot`). Anything else is refused with the field named.

**API.** `POST /api/v1/repos/inspect {path}` returns `{path, remote, host, url, default_branch, has_pipeline}`. `POST /api/v1/repos/{id}/clone {dest}` clones a registered repository with its own token or the host token (`Engine.CloneRepo`) and returns `{path}`. Registration stays `POST /api/v1/repos`, a token `PUT /repos/{id}/token`, the access check `POST /repos/{id}/token/check`.

**Page.** An Import button in the header opens a panel with two tabs. *Local folder*: a path, Inspect, then the detected host, URL, protected branch and merge strategy (editable), whether the folder has a pipeline, and the token: the host token, or one for this repository only. *Clone a remote*: a URL with the host detected as you type, a destination folder (default `~/dev/<name>`), the same token choice. Import registers, stores the token when one is given, checks access, and for a clone clones; each step reports on its own line, and a failure after registration says what is registered and what is left. The read-only footnote and the empty state change to point at Import.
