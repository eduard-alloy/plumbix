# WU-077: Screenshots in the README

**Status**: ⚪ Planned · **Features**: docs · **Estimate**: short · **Kai**: 5FRKY7 (workstream XVACVT, milestone O1 HGFMS1) · **Follows**: WU-073 · **Source**: outside feedback of 2026-11-06, point 5; A48

## Goal

A visitor sees the interface before reading about it: the queue of changes that need a person, a verdict with its evidence per criterion, and the merge action.

## What is wrong today

- The only images in the repository are `web/design/status-palette-light.png` and `-dark.png`.
- The README describes the interface in one comment line of the quickstart.
- Whether the GitHub App's check runs are visible on the public repository's pull requests, which would be live proof of dogfooding, is unverified.

## Design

1. **Three views**, each in light and dark: the changes list filtered to `needs_human` with two or three seeded changes; a change page showing a verdict with per-criterion evidence from both validators; the same page with the Approve and Merge actions in view.
2. **Seeded data**: a throwaway data directory on the local server with a bare repository and three submitted changes, so no real repository or token appears in a frame. The memory note on checking the UI with headless Chrome is the capture method; frames at a fixed viewport, both themes, cropped to the content.
3. **Placement**: `docs/images/<view>-<theme>.png`; the README shows the light frame next to the concept it illustrates with alt text that says what is in it, and uses `<picture>` with `prefers-color-scheme` so the dark frame shows on a dark GitHub theme.
4. **Live proof**: check `eduard-alloy/plumbix` for `plumbix/gate` check runs on a recent pull request or landed commit. If visible, the README links one; if not, the completion section says why (the public repository uses API submissions, or the App is not installed there) and nothing is linked.
