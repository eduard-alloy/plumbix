# WU-009: Azure DevOps adapter

**Status**: ✅ Complete (2026-10-16) · **Features**: F-005 · **Estimate**: 2-3 hours

## Goal

Plumbix fetches, polls and validates repositories hosted on Azure DevOps with a personal access token, through the same host boundary GitHub uses. Nothing outside `internal/host` learns a new host.

## Context

- ARCHITECTURE.md 4.5 (host boundary), Q13 (Azure DevOps PAT scoped to code read/write, kept in the secrets file, never logged).
- WU-008 built the boundary: `Host{Kind, Auth, TokenExpiry}`, askpass credentials, `ListHeads`, the poller's daily token check.
- `internal/change` already accepts `https://dev.azure.com/<org>/<project>/_git/<repo>` and `https://<org>.visualstudio.com/<project>/_git/<repo>`.

## Design

**Credentials.** Azure DevOps takes a PAT as the basic-auth password and ignores the user name. The adapter sends user `plumbix` and token `PLUMBIX_AZURE_DEVOPS_TOKEN`. Without a token the repo is fetched anonymously, which only works for public projects.

**Token expiry.** Azure DevOps does not report a PAT's expiry to the PAT's holder: the token lifecycle API needs a Microsoft Entra ID sign-in, not the PAT. Instead the user, who picks the expiry date when creating the PAT, records it as `PLUMBIX_AZURE_DEVOPS_TOKEN_EXPIRES=YYYY-MM-DD` in the secrets file. The poller's daily check then warns 7 days ahead exactly as for GitHub. Without the date there is no warning. A malformed date is reported by name, never with the token. The adapter makes no network calls; a rejected token shows up as a fetch failure in the poller log.

**Nothing else changes.** Fetch, `ListHeads`, poller, engine, API and CLI already work through the boundary.

## Acceptance criteria

- **AC-1**: The adapter returns credentials from the secrets and fetches anonymously without a token.
- **AC-2**: Expiry comes from the secrets date: parsed when present, absent otherwise, and a bad date gives an error that names the setting and not the token.
- **AC-3**: `FromSecrets` registers the adapter for host `azuredevops`.
- **AC-4**: Through the engine, a repo registered as `azuredevops` is fetched from a basic-auth git server with the right token and fails with a wrong one, without leaking the token.
- **AC-5**: `make check` and `make integration` pass.

**Decisions**
- Token expiry comes from `PLUMBIX_AZURE_DEVOPS_TOKEN_EXPIRES` in the secrets file, not from a network probe. Azure DevOps does not expose a PAT's expiry to the PAT, and a probe of a profile endpoint could fail on a correctly scoped code-only token, giving false alarms. A rejected token already surfaces as a fetch failure in the poller log.
- Basic-auth user name `plumbix`: Azure DevOps ignores it when the password is a token, and a fixed non-empty name keeps git from prompting.
