# WU-059: Plumbix's own merges satisfy a required gate

**Status**: ✅ Complete (2026-10-28) · **Features**: F-010, F-001 · **Estimate**: one session · **Kai**: 10M7QY (workstream F8QK66, milestone M2 PZTRDV) · **Follows**: WU-061

## Goal

Found while landing the A40 docs: a ruleset's required status check applies to every update of the branch, not only to pull requests. The owner's `main` requires `plumbix/gate` (integration-bound, no bypass actors), so GitHub refused Plumbix's own squash push ("push declined due to repository rule violations") and `merge_change` reported `push_rejected: the remote branch moved`, because `gitops.pushError` reads git's word "rejected" as a moved branch. Until now every change to Plumbix itself had to go through a pull request.

Two things, then: Plumbix's own merge must carry the gate check on the commit it lands, and a push GitHub refuses for its rules must be reported as that.

## Design

- **Landing through a holding ref** (`Engine.Merge`, `internal/engine/merge.go`): after the landing commit is built and before the target is pushed, the engine asks a `Landing` (an interface the engine owns; `pullrequest.Lander` implements it, wired in `serve.go`) whether the target branch requires `plumbix/gate`. When it does, the engine pushes the commit to `refs/plumbix/landing/<change id>` (a ref outside `refs/heads/`, so the poller never runs a pipeline on it and GitHub shows no branch), the Lander posts a `plumbix/gate` check run on that commit as the App (conclusion `success`, the run's combined result embedded under `plumbix-result/v1` as on a pull request, the title saying Plumbix landed the validated tree of run head `<sha>`), then the engine pushes the target with the lease as before and deletes the holding ref. When the requirement is unknown (no API, no administration read) or not there, the merge pushes as before, one push. Rejected: the App or the user as a ruleset bypass actor (GitHub's rule insights would show every Plumbix merge as a bypass, which Chart-AI records as one); requiring a pull request for everything (the API shape stays); posting the check after the push (GitHub refuses the push first).
- **The refusal named** (`gitops.ErrPushRefused`): git's output for a rule refusal (`GH013: Repository rule violations`, `push declined due to repository rule violations`, `protected branch hook declined`) becomes its own error carrying the rule lines GitHub printed, checked before the moved-branch classification. The API answers `push_refused` (409) with the rules in the message; the engine's message says what to do (the gate was posted, so another rule holds the branch; or the requirement could not be read, so give the token or App administration read).
- **gitops**: `Mirror.PushRef(ctx, ref, sha)` (forced: the ref is Plumbix's own) and `Mirror.DeleteRef(ctx, ref)`.
- **Not in this unit**: Azure DevOps; a landing for `merger: plumbix` pull requests beyond what WU-056 needs.
