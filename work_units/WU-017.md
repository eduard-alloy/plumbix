# WU-017: Web interface, log panel, diff view, alerts, repositories

**Status**: ✅ Complete (2026-10-16) · **Features**: F-004, F-007 · **Estimate**: 6 hours

## Goal

The second half of the interface from `web/design`: the step log panel, the diff view with findings inline, the alerts and repositories pages, and the design-system reference page. After this unit every screen in the handoff exists.

## Context

- `web/design/README.md` sections 4 to 7 and the prototype's `logVM`.
- WU-011 left evidence links opening raw logs in a new tab and the Diff section showing a file list; both are replaced here.
- The API lists a run's steps only once they finished (WU-011). A log can therefore only be opened for a finished step, so the panel's Follow mode has nothing to follow yet. It is left out and noted; the footer always shows the finished form.

## Design

**Log panel** (`ui/LogPanel.tsx`). A fixed right panel, `min(860px, 100vw − 208px)`, not modal, `role="region"`. Header: step name, StatePill, validator tag, `esc close`, ×; meta line with change id, run id, iteration, duration, exit code. Toolbar: search with `n/N` inside, Enter or Next jumps to the next match, Wrap toggle. Body: line numbers in a 56px gutter, `pre` or `pre-wrap`, lines matching FAIL / Error / errored / failed in red, `$ ` command lines dimmed, matches highlighted with `--hit` and the current one with `--hit-strong`. Footer: "Step succeeded. Full log, fetched on open." and the line count. `/` focuses the log search while the panel is open; Esc closes the panel before anything else. Opened from evidence rows, verdict steps and criterion evidence paths (`evidence/<step>/…`). Pure helpers in `vm/log.ts`: `splitLines`, `lineTone`, `highlight`.

**Diff view** (`ui/DiffView.tsx`). File rows (32px, path, +add −del); for files with hunks, a hunk header line and a grid `44px 44px 16px max-content` of old number, new number, sign and code with `--diff-add` / `--diff-del`. Findings with a file and line render inline under that line (plain severity pill, message, validator). A `file:line` link in Findings loads the diff if needed and scrolls to the line, which gets an accent inset outline; when the line is not in a hunk, the file row is highlighted instead. Binary and truncated cases say so.

**Alerts** (`pages/AlertsPage.tsx`). Open alerts first; `Show resolved (N)` fetches with `include_resolved=true` and lists them under a Resolved label at reduced opacity. Each row: kind label ("Commits without a verdict", "Token expires soon" or "Token check failed" when the message says the check failed), mono kind, repository name, when; the message; for bypass alerts a mono table of sha, author, time and subject; a hint line; a quiet Resolve button. Empty copy from the design.

**Repositories** (`pages/ReposPage.tsx`). Read-only table: id, host, URL, protected branches, strategy, change count; footnote; empty state.

**Design system** (`pages/DesignPage.tsx`, route `/design`). Tokens, type scale, the full state encoding table and the components, rendered twice side by side with `data-theme="light"` and `data-theme="dark"` containers so both themes are visible at once. It is a reference for building, not navigation: reachable by URL only.

**Not in scope.** Follow for live logs (needs running steps in the API), editing repositories, push notifications.

## Acceptance criteria

- **AC-1**: The log panel opens from evidence rows, verdict steps and evidence paths; shows numbered lines; search counts matches and Enter or Next moves the current one; Wrap toggles; Esc and × close it; `/` focuses its search while open.
- **AC-2**: The diff view renders hunks with numbers and signs, findings inline under their lines; `file:line` opens the diff and highlights the line, or the file when the line is outside the hunks.
- **AC-3**: Alerts lists open alerts with commit tables, resolves one, toggles resolved ones in.
- **AC-4**: Repositories lists every repo with its change count and shows the empty state.
- **AC-5**: The design-system page renders both themes with the encoding table and components.
- **AC-6**: `make check` and `make integration` pass.

**Decisions**
- No Follow mode yet (see Context); the footer always reads "Step <status>. Full log, fetched on open."
- Alerts shows the repository by name, not id, and labels token alerts from the message ("check failed" → "Token check failed").
- The design page is reachable by URL only (`/design`); it is a reference, not a destination.
- The hunk header shows the full `@@ -a,b +c,d @@ context` line rather than only the context, so the numbers are visible where the diff is read.

**Still not seen in a browser.** Four screens and a panel were built headless against the handoff's measurements. A visual pass is the first thing to do with WU-012's self-hosting run.
