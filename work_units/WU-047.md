# WU-047: Azure importer: templates and template expressions

**Status**: ✅ Complete (2026-10-20) · **Features**: F-014 · **Estimate**: one session · **Kai**: K5NE5F (workstream TCVR9R, milestone I1) · **Decisions**: A36, A37

## Goal

Most real Azure pipelines are built from templates. WU-046 kept every template reference as one disabled step (reason `template`), so a pipeline built from a stage template was a single step that could never run. This unit reads the templates and inlines them at import time, then converts the result the way WU-046 converts any job. Templates can live in the same repository or in another repository registered in Plumbix. Variables and conditions are WU-052.

## Design

- **Lookup.** `Source.Convert` gets a third argument, `importer.Lookup`:
  - `Files` holds the repository's YAML files at the previewed commit.
  - `Repos` resolves another repository the way the source system names it, returning that repository's YAML files and a label such as `orders-infra at 1a2b3c4`.
  - `Preview` passes the lookup through unchanged.
- **Template references.** A `template:` item in a `stages`, `jobs`, `steps` or `variables` list is replaced by the template file's list of the same kind, expanded with the parameters it is given. Templates can nest. A root `extends: {template, parameters}` uses the template's `stages`, `jobs` or `steps` as the pipeline body; the root keeps its own triggers, resources and variables.
- **Paths.**
  - A path with a leading `/` is from the repository root. Any other path is relative to the folder of the file holding the reference.
  - `path@alias` reads from the repository named in the root pipeline's `resources.repositories`; `@self` is the repository being imported.
  - Inside another repository's template, a reference without `@` stays in that repository.
  - A path that leaves the repository is an error.
- **Repository resources.** The engine resolves only repositories already registered in Plumbix:
  - type `git` (Azure Repos): `Project/repo`, or plain `repo` meaning the same project as the importing repository, in the same organisation;
  - type `github`: `owner/repo`.
  - Names are compared case-insensitively and URL-decoded.
  - `ref: refs/heads/x` or `x` reads branch `x`. With no ref it reads `main`, else `master`, else it is an error.
  - Tags, other types and unregistered repositories are errors. The note says to register the repository.
- **Parameters.**
  - A template's `parameters` can be the list form (`name`, `type`, `default`, `values`) or the old map form (name to default).
  - A parameter that is required but not given, a value outside `values`, and a parameter the template does not declare are errors.
  - Values keep their type: boolean, number, string, or object (a whole stage, job or step list).
- **Root parameters.** These are run-time parameters with defaults. WU-046 disabled the pipeline (reason `trigger`) for any of them. Now they are expanded with their defaults, with a note that a run always uses the defaults. Only parameters with no default still disable it.
- **Expressions** `${{ }}` (compile time):
  - Values: `parameters.x`, `parameters['x']` and property paths, the loop variable of `each`, and `variables.x` for variables defined inline at the root. An undefined name without a dot is empty, as in Azure. A name with a dot, such as a predefined variable, is unsupported.
  - Literals: strings, numbers, `true`, `false` and `null`.
  - Functions: `and`, `or`, `not`, `xor`, `eq`, `ne`, `gt`, `ge`, `lt`, `le`, `in`, `notIn`, `contains`, `containsValue`, `startsWith`, `endsWith`, `coalesce`, `format`, `join`, `lower`, `upper`, `replace`, `length`. Names and string comparisons ignore case, as in Azure.
  - Where they work:
    - A scalar that is a whole expression takes the value, so a step list can be passed as a parameter. Text with embedded expressions is a string.
    - The `${{ if }}`, `${{ elseif }}` and `${{ else }}` directives work in mappings and lists.
    - `${{ each x in ... }}` works over lists and mappings, with `x.key` and `x.value`.
    - A list item that evaluates to a list is spliced in.
  - Anything else is unsupported. That includes `${{ insert }}` and other functions.
- **Failures stay visible.** A template that cannot be read or expanded keeps its reference as one disabled step, reason `template`, and the note says why. Stage and job references fail this way; step and variable references disable the job that holds them. If the root file's own expressions fail, it is converted unexpanded as in WU-046, with a note.
- **Limits.** At most 100 template files per pipeline, nesting depth 20, and 100,000 expanded nodes. Past any limit, expansion stops with an error.
- **Provenance.** An inlined job's `source` names the file that defines it (`path` or `path@alias`) and its line. The hash covers the job after expansion, so re-check (WU-048) sees changes in templates and parameters. A pipeline note lists the templates inlined from other repositories, with each repository's label.
- **Engine.** `ImportPreview` builds the lookup. Other repositories are fetched once per preview and keep the same YAML-only, 1 MiB-per-file rule.
- Fixtures are made up, never a real project's.

## Acceptance criteria

| # | Criterion | Check |
|---|---|---|
| AC-1 | Expressions evaluate as listed; unsupported ones are errors. | expr tests |
| AC-2 | Stage, job, step and variable templates, nested ones and `extends` inline with their parameters; if/elseif/else, each and splicing work; parameters are type-checked. | azure template tests |
| AC-3 | Root parameters with defaults are expanded and noted; those without a default still disable the pipeline. | azure tests |
| AC-4 | Templates from a registered repository resolve by resource; unregistered repositories, tags and missing files disable with a note; limits hold. | azure and engine tests |
| AC-5 | Inlined steps carry their defining file and a hash after expansion; every converted fixture parses. | azure tests |
| AC-6 | `make check` passes; ARCHITECTURE, CONSTRAINTS, PROJECT and CONTEXT_LOG describe it. | |

## Steps

1. Expression evaluator, test first.
2. Expansion of templates, directives and parameters over a lookup, test first per construct.
3. Converter uses the expansion; failure placeholders; provenance.
4. Engine lookup with registered repositories.
5. Docs.

## Completion

**Delivered**:
- `importer.Lookup`, `RepoRef`, `Tree` and `Step.File`; `Source.Convert` and `Preview` take the lookup.
- `azure/expr.go`: the compile-time expression evaluator.
- `azure/template.go`: template references in stages, jobs, steps and variables lists, `extends`, directives, splicing, parameters and limits. Failures stay as references, and the converter disables them with reason `template` and the cause.
- Root run-time parameters with defaults are expanded and noted.
- Stage names are made unique.
- Engine `matchRepo`, `resourceBranch` and `importRepos`: registered repositories only, each read once per preview.
- API and OpenAPI: step `file`.

**Evidence**:
- `TestExpressions`, `TestExpressionErrors` and `TestTruthiness`.
- `TestStageTemplate`, `TestJobAndStepTemplates`, `TestExtends`, `TestTemplateFailures`, `TestRootParameters`, `TestRepositoryTemplates`, `TestDirectivesInMappings`, `TestExpansionLimits` and `TestRuntimeVariable`.
- `TestMatchRepo`, `TestResourceBranch` and `TestImportPreviewTemplates` (engine), plus `TestImportPreviewEndpoint`, which checks `file`.
- A local dry run (not committed) over a real repository's 26 Azure pipelines: every template now inlines, and no step is disabled for `template` any more (it was the service pipelines' only step blocker). What remains is `host` 51, `task` 18 and `deployment` 9, with notes on variables, secrets and conditions.
- `make check` green.

**Found on the way**:
- One stage template used twice produced duplicate stage names, so the file did not parse. Stage names are now made unique.
- A template reference's step name kept `.yml` when it had an `@alias` (from WU-046).
- A variable set by a `$[ ]` runtime expression was used as a literal value. It now disables the step with reason `variables`.

**Deferred**:
- WU-052: run variables and simple conditions.
- WU-048: tag refs for repository resources, and re-check of inlined templates.
