# WU-057: Origin of a change in the web

**Status**: ✅ Complete (2026-10-28) · **Features**: F-010, F-004 · **Estimate**: short · **Kai**: A6PVGN (workstream F8QK66, milestone M2 PZTRDV) · **Follows**: WU-054, WU-055

## Goal

After the first pull requests gated on Plumbix's own repository, the owner asked to tell pull-request changes from direct ones at a glance. A change carries `pull_request` since WU-054; the web showed nothing of it.

## Design

- **`OriginVM`** (`web/src/vm/changes.ts`, `origin(c)`): `pr` with the label `PR #n`, a title and the pull request's URL, or `api` with the label `API`. The row view model and the change page header carry it.
- **`OriginTag`** (`web/src/ui/OriginTag.tsx`): the `.tag` shape with an origin tint, violet for a pull request and neutral for the API, from the status palette tokens. The words carry the meaning and the tint helps a scan, as the state encoding rule says. Inside a list row, which is a button, it is a span; on the change page it links to the pull request in a new tab.
- **Changes list**: the tag sits before the title; an `Origin` select (all, pull requests, API) joins the repository and state filters and is kept in the URL as `origin=pr|api`; Clear resets it.
- **Change page**: the header's meta line gains `from PR #n` or `from API`.
- **Runs** carry no tag of their own: the web lists runs only under a change, whose header says where it came from.
