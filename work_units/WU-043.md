# WU-043: Import polish: decoded names, missing host token, plain credentials error

**Status**: ✅ Complete (2026-10-19) · **Features**: F-001, F-004 · **Estimate**: small · **Kai**: QR37JJ · **Decision**: A35

## Goal

The owner's first real import, an Azure DevOps repository, showed three rough edges: the name read `Easy%20Claim`, the panel let them pick "Use the host token" when no Azure DevOps host token was set, and the access check then failed with git's "could not read Username … terminal prompts disabled". WU-042's review also left two notes.

## Design

- **Names.** `repoName` and the import panel's `remoteName` decode URL encoding (`decodeName`), keeping text that is not valid encoding. Every place that shows a repository's name uses them.
- **Missing host token.** The import panel reads which host tokens Settings has. When the chosen host has none, it says so, disables "Use the host token", and treats the repository as needing its own token: the import button waits for one.
- **Plain error.** When git would prompt for credentials, `gitops` returns `ErrNoCredentials`: "no token for this repository: set one on its card on the Repositories page, or the host token in Settings". The access check, fetches and clones show that instead of git's prompt message.
- **WU-042 notes.** Publishing prepares the askpass script before the host creates anything; the OpenAPI text and WU-042 no longer claim the folder always has origin after `push_failed`.

## Completion

**Delivered**: `decodeName` in `vm/changes.ts`, used by `repoName` and `remoteName`; host token awareness in `ImportPanel` (`hostTokenSet`, `effective`); `gitops.ErrNoCredentials` from the command runner; askpass before creation in the publish route; the OpenAPI and WU-042 wording. Docs as listed.

**Evidence**: the repository names test (vm); the missing host token page test (an Azure DevOps repository with a space in its name, registered and listed with its decoded name); `TestFetchWithAuth`'s credential-less fetch (gitops); the askpass case in `TestPublishRefusals` (api). The two earlier page tests that rely on a host token now set one. `make check` green.

**Deferred**: none.

## Fixes

- 2026-10-19, review of the landing change: a push without credentials stopped being classified as push denied, because the runner now reports `ErrNoCredentials` without git's text; `pushError` recognises it again and the classifier test uses the runner's error. The import panel failed open when Settings could not be read; it now asks for a repository token in that case, tested. A clone without credentials is tested for the plain error, and the askpass test pins the status and an unchanged folder.
