# AI reviewers

Reviewer profiles, the external review loop, and what happens when a review cannot be answered. Back to the [README](../README.md).

## The external review loop

An AI review can run outside the pipeline too: a validator step with `external: true` waits for a verdict, and `plumbix review --watch` on any machine with Claude Code installed pulls the review brief, reads the change in a checkout, and posts the verdict, using whatever Claude login that machine already has. The loop does in a scripted way what a person at that machine would do with Claude Code, one session per review; whether your plan allows that use unattended is between you and the vendor, and an API profile with its own key is the alternative. A review the platform closes without a verdict says why (WU-068): `review.expired` in the event stream carries `reason` (`timed_out`, `run_cancelled` when the run was cancelled, by a newer iteration or a closed change, `server_stopped`, `server_restart` after a crash recovery), the reason stays on the review, a verdict or log line posted afterwards is refused with 409 naming it, and `review.released` says `reviewer_gone` when a claim went back because the loop never received the brief. A reviewer that cannot do its job gives the review back itself (WU-071): `POST /api/v1/reviews/{id}/fail` with `checkout_failed` (the head could not be cloned) or `reviewer_error` (Claude produced no verdict) and its own words in `message`; the review expires with that reason and message, the step errors at once instead of waiting out its timeout, and the change waits for a person. A private repository needs no git credential on the loop's machine: the loop asks `POST /api/v1/reviews/{id}/credential` with the claim's token for what the server fetches the repository with (its own token, else the host's; 204 when the server fetches anonymously, and the machine's own git access applies as before) and hands it to git through the askpass script in its environment only, never on the command line, in a URL or in a log. Closing a change cancels the run still going for it, so a review waiting there expires as `run_cancelled`. A session the loop starts says who launched it: `PLUMBIX_LAUNCHER=review`, `PLUMBIX_REPOSITORY` (the registration's url byte for byte as the API returns it), `PLUMBIX_REPO_ID`, `PLUMBIX_CHANGE`, `PLUMBIX_RUN` and `PLUMBIX_REVIEW` in its environment, so an observer's hook inside the session can tell the repository and the launcher without a rule on a machine path; the AI validator image sets `PLUMBIX_LAUNCHER=validator` and `PLUMBIX_CHANGE` ([contracts/launcher.md](../contracts/launcher.md), WU-069). After a restart Plumbix never starts an iteration itself: a run that ended because the server stopped (its error reads "interrupted because the Plumbix server stopped" on a graceful stop, "interrupted: the Plumbix server stopped during this run" after a crash recovery) leaves the change at `needs_human` as a hold that a person or a client releases with `POST /api/v1/changes/{id}/validate` (`plumbix change validate`).

## Reviewer profiles

Which model judges is a reviewer profile, defined under AI reviewers in Settings. API profiles (Anthropic, or any OpenAI-compatible endpoint: OpenAI, Gemini, Grok, Kimi, DeepSeek, Groq, a local server) judge from inside the pipeline with their own key, billed per token; a Claude Code profile is the loop above, on that machine's Claude subscription, with its model and whether it may run commands; a Claude Code in-the-pipeline profile runs the same Claude Code inside a `plumbix-claude-code-validator` step on a token you mint with `claude setup-token` (or an API key), for a server where no loop is signed in. A validator step names its profile with `reviewer: <name>`; steps that name none get their family's default. Two validator steps with two profiles run side by side, so models can be compared on the same change; mark the second one `advisory: true` and its verdict is recorded and shown but never counted. Reasoning models think before they answer, sometimes for minutes: set the profile's effort, or a step's `effort: low`, and the log shows how many reasoning tokens a verdict cost.
